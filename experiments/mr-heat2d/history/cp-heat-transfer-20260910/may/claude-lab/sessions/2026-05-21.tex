\subsubsection*{Summary}
Built a new experiment to find where the empirical-quadrature (EQ) node
count \texttt{n\_eq} stops buying ROM accuracy, swept it across 3 NM-ROM
decoders. Fixed several bugs; the CP-decoder curve is the one clean,
verified result.

\subsubsection*{Decisions / surprises}
\begin{itemize}
  \item The core bug: the EQ builder silently zero-padded --- when a target \texttt{n\_eq} exceeded the node count NNLS returned, it appended index entries with weight exactly 0.0. Zero-weight nodes are inert, so every ``\texttt{n\_eq}=500/2000/16384'' cell secretly used the same $\sim$200-node rule; the SIREN and linaff sweeps measured nothing. New builder never zero-pads: truncate-to-top-$k$ below the NNLS count, per-target NNLS in range, random densification above the snapshot ceiling, full-domain at DOF.
  \item SIREN's single-stage cold-start solve fails (rel-L2 $\sim$1.5, the known $z{=}0$ basin stall); fixed by switching the adapter to the cross-composite solver (coarse anchor checkpoint cold-seeds a fine lap-checkpoint warm solve).
  \item CP adapter was first pointed at a regressed multires checkpoint (rel-L2 floored at 0.39 even at full domain); fixed by rebuilding the CP runner from the verified \texttt{best-results} reference (rel-L2 4.84e-4).
  \item linaff numbers are currently untrustworthy --- a 0.188 rel-L2 anomaly at \texttt{n\_eq}=100--200 appears in the full multi-decoder sweep, but every isolated diagnostic of the same adapter/checkpoint gives $\sim$1e-3. Five hypotheses refuted; not root-caused. User decision: linaff's autoresearch folder is debug-first.
  \item For the CP decoder, aggressive hyper-reduction does not pay off --- accuracy improves monotonically to full-domain integration (no knee), and wall-clock is nearly flat (2.5--4.7 ms across the full 2000$\times$ \texttt{n\_eq} range), so integrating over the whole domain costs almost nothing.
\end{itemize}

\sessionhead{2}{20:08}{linaff-debug}{inr-siren-speed-accuracy}{1b38163}

\subsubsection*{Summary}
Phase-1 debug of the \texttt{linaff} (\texttt{LinearAffineZ}) decoder's
EQ \texttt{n\_eq} sweep, per the \texttt{2026-05-21-EQ-LINAFF}
autoresearch brief. Root-caused the unexplained rel-L2 spike at
\texttt{n\_eq}=100--200 and produced a verified-correct \texttt{n\_eq}
curve. The spike is genuine, not a bug.

\subsubsection*{Files touched}
\begin{itemize}
  \item \texttt{Experiments/2026-05-21-EQ-LINAFF/run\_eq\_sweep\_l40s.slurm} --- isolated \texttt{--only linaff} sweep on a free l40s GPU (ROM-only debug; no A100 needed).
  \item \texttt{.../scripts/bisect\_spike.py} --- per-cell mechanism dump: rule regime, weight ratio, generalisation error, and the GN-vs-encoder EQ-loss comparison that exposes the spurious reduced minimum.
  \item \texttt{.../scripts/verify\_fix.py}, \texttt{verify\_weights.py}, \texttt{verify\_selection.py} --- three falsification tests for candidate fixes.
  \item \texttt{.../FINDINGS.md} --- the Phase-1 writeup; \texttt{results.csv}, \texttt{plots/}, per-cell JSON committed.
\end{itemize}

\subsubsection*{Decisions / surprises}
\begin{itemize}
  \item The spike reproduces deterministically in a fresh, single-decoder, isolated process --- so it is not a 3-decoder-job artifact, state leak, ordering effect, or hardware effect. The brief's framing (``every isolated diagnostic gave $\sim$1e-3'') came from diagnostics that happened to hit lucky NNLS rules; the honest full-driver curve has the spike.
  \item \texttt{results\_BUGGY\_865541.csv.bak} in the origin folder is mislabeled --- it is a stale pre-865541 CSV from the old zero-padding builder (\texttt{n\_eq}=50/100/200 collapse to one identical 0.188 row), not job 865541's output. Job 865541's real per-cell JSONs show distinct genuine rules.
  \item Mechanism: the linaff manifold can represent every test solution (encoder $z$ gives rel-L2 3--6e-3), but the EQ-reduced Gauss-Newton objective $\tfrac12\sum_{j\in\text{EQ}}w_j R(z)_j^2$, sampled at \texttt{n\_eq}$\sim$100--700 of 16384 nodes, has spurious minima --- GN converges to a $z$ with \emph{lower} EQ residual than the true solution yet full-domain rel-L2 0.2--0.4.
  \item Three EQ-rule fixes were tested and \emph{all rejected}: NNLS rank headroom, EQ weight conditioning (uniform/clipped/sqrt), and node selection (NNLS-top-k / random / uniform sub-lattice). No node set of size 100--700, however chosen or weighted, recovers the solve. The failure is intrinsic to sparse residual sampling for the affine decoder, not a defect of the EQ-rule construction.
  \item The verified curve has a genuine \emph{valley of failure} at \texttt{n\_eq}$\sim$100--700: linaff works at \texttt{n\_eq}$\le$64 and at \texttt{n\_eq}$\ge$4096, but not in between. That valley is the correct, reproducible result, not an artifact to be removed.
\end{itemize}
