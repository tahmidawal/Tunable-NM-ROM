# Codex design and code audit — hires-burgers, 2026-09-20 (before any GPU job)

Auditor: Codex CLI v0.155.1, model `gpt-6-astra`, `codex exec --sandbox read-only`. The sandbox
could not start a shell on this machine (`bwrap: loopback: Failed RTM_NEWADDR`), so a first attempt
returned "audit blocked". The sandbox was **not** lifted (the protocol specifies read-only);
instead DESIGN.md, `hops.py`, `hfast.py`, `hires.py`, `config-2048.json`, `topfix.py`, `arms.py`,
`engines.py` and the relevant `varpro.py` excerpts were inlined on stdin and audited from text.
`fast.py`, `iterative_paths.py`, `ladder.py` and `sep_common.py` were not supplied and are outside
this audit. The audited text was the pre-restructure driver; dispositions below say what changed.

## Codex output, verbatim

57,663
1. **Refined-reference failure can prevent completion after the entire timed campaign.** `hires.py`: `"q_ref, _ = e.make_fom(rf, rt)"` and `"fr, it, rn = q_ref(...)"` have no OOM handling or fallback. Config requests `8192²`, 800 time steps and Newton tolerance `1e-11`, while the ROM bank and compiled subjects remain resident. A deadline checked before invocation cannot stop an overlong solve. This is a substantial resource risk, not a proven H200 OOM from the supplied text. **Minimal fix:** save the completed panel first; release unnecessary device objects; run the reference under an actual execution deadline; catch failures and implement the declared, explicitly labelled smaller-reference fallback.

2. **An unconverged FOM can become the accuracy reference.** `hires.py`: `"truth[c] = f"` requires finite fields but only records `"converged=bool(...)"`. The refined reference likewise records residuals without requiring convergence. Every accuracy verdict can therefore use an inadequately solved reference. **Minimal fix:** require finite residuals and convergence before accepting either reference; otherwise mark dependent accuracy claims unscored.

3. **The negative control is altered before testing, and its required failure is never enforced.** Config gives rule `"name": "bad"` the option `"refit": "state"`. `hires.py` then replaces its weights through `"w, finfo = H.refit_weights(...)"`. This tests a repaired support, not the historically regressing rule. There is also no control-failure gate. **Minimal fix:** retain the original transferred weights as `bad_original`; label any refit separately; explicitly test both certificate rejection and measured regression. A historical regression need not persist at a new mesh, so failure of that expectation should invalidate the control argument, not trigger tuning until it fails.

4. **Certification does not govern deployment or completion.** `hires.py`: `"subjects.append(name)"` includes uncertified rules, and the script ultimately sets `"rep['complete'] = True"`. There is no implementation of DESIGN’s `"cheapest certified arm with evolved error ≤ 1 %"` selection, no speedup verdict, and no mandatory dense fallback when certification fails. **Minimal fix:** compute an explicit eligibility table, per-case timing medians, comparator speedups and campaign verdict; distinguish execution completion from contract satisfaction.

5. **Certification is for one solver setting but stored as a rule-wide property.** `hires.py` skips deployed certification unless `"b['gtol'] != min(...)"` is false and `"b.get('solver', 'lu') != 'lu'"` is false. It then writes `"info['certified_primary']"`. The `1e-3` and Cholesky arms can visit different states from the certified `1e-6` LU arm. **Minimal fix:** certify each deployable arm’s population and key the certificate by rule, tolerance and solver.

6. **Parity is incomplete and never becomes a gate.** `hires.py`: `"if not name.endswith('_fast'): continue"` excludes `_fast_chol`; `"if twin not in subjects: continue"` silently skips lattice and bad-rule arms without base twins. Recorded differences are never compared with the stated `1e-9` threshold or used to relabel failures. **Minimal fix:** map every optimized arm explicitly to its base comparator, record pass/fail and missing coverage, and label nonpassing arms as distinct algorithms.

7. **The named cheaper FOM controls are not enough to establish an accuracy-matched speed claim.** Config combines `"ntol": 0.01` with `"ltol": 0.5`, while DESIGN calls the headline comparator the `"fastest tested FOM whose error is ≤ the ROM's"`. Such a loose inner solve may be cheap or may waste Newton iterations; the supplied text does not establish either. It also leaves intermediate accuracy/cost settings unexplored. **Minimal fix:** retain these controls but include a predeclared, competent inner-tolerance sweep for the relaxed FOM; describe the result strictly as fastest *tested*. Comparing against a tight reference alone would overstate the speed advantage.

8. **The timed I/O contract includes unequal diagnostics and potentially host dispatch.** `hires.py`: `"v = invoke(b, u, c)"` followed by `"jax.block_until_ready(v)"` waits for each complete return tuple. ROM returns trajectories and diagnostics; FOM returns another diagnostic set. The interval also includes Python dispatch, and the same-grid `iterative_paths` implementation is absent, so its internal timing scope cannot be verified. **Minimal fix:** benchmark matched field-output wrappers, collect diagnostics separately, and retain a separately labelled instrumented-query timing. The shown upload/download boundaries themselves are symmetric.

9. **Large host-memory retention is uncontrolled.** `hires.py`: `"kept[(name, c)] = (f, ...)"` retains every full six-field result, and config does not set `keep_for_reference`. There are 45 configured subjects: their six-case fields alone occupy approximately **54.4 GB** at `L=2048`, excluding truth, temporary arrays and runtime memory. H200 capacity does not establish available host RAM. **Minimal fix:** persist results and reload one case at a time for parity/reference comparisons; retain only required fields in memory.

10. **GPU memory safety is not established by avoiding `Phi`.** `hops.py`: `"via_host = (n * bank.dim * 8 > 24e9)"` selects `bank.on_grid` at `L=2048`, where `G` alone is about **17.16 GB**. Its construction peak depends on the omitted decoder implementation. `hires.py` also retains all subjects, folds and executables and rewarms them together through `"for n in timed"`. Several allocation-heavy phases have no OOM handler. **Minimal fix:** budget and measure peak memory, use explicit bounded construction, and manage executable/arm residency. The supplied code does **not** justify claiming an inevitable 2048² OOM.

11. **Strict JSON serialization can abort on diagnostic NaNs even when fields are finite.** `hires.py` records `"worst_joint_stationarity=float(np.max(gj))"` and `"max_relative_residual=float(rn.max())"`; `hops.py` records unguarded `rho` statistics. Field finiteness does not imply diagnostic finiteness. If `LD.dump` uses `allow_nan=False`, any NaN/Infinity raises; `LD.dump` itself was not supplied. Also, `"rn > fs['ntol'] * ..."` does not count NaNs as stalled. **Minimal fix:** classify nonfinite diagnostics as failures and serialize them as `null` with an explicit status.

12. **Population provenance claims convergence without checking it.** `hires.py` labels the source `"converged per-step states"` but checks only `"np.isfinite(wv).all() and np.linalg.norm(wv[-1] - wv[0]) > 0"`. A trajectory with almost every step stalled can pass. **Minimal fix:** record per-step reasons/residuals and require the declared convergence policy, or accurately label the population as including stalled states.

13. **Reproducibility checks can pass vacuously or fail without consequence.** `hires.py` stores the cohort comparison in `"passed=(None if want is None else want == ...)"` without asserting it. The repetition gate uses `"all(x['identical_to_first_rep'] for x in rep['invocations'])"`, which passes an empty panel; the first repetition compares with itself. Config’s five repetitions avoid the empty-panel case in a normal run, but the code does not enforce that contract. **Minimal fix:** require the cohort hash, complete subject/case/repetition coverage and at least five repetitions before evaluating the gate.

14. **The output-identity check is weaker than the stated claim.** `hires.py`: `"chk = (float(f.sum()), float(np.square(f).sum()), sha_array(f[:, ::sub, ::sub]))"`. Different full fields can share these statistics and restricted samples. **Minimal fix:** hash the complete host field, which has already been downloaded.

15. **The “quick answer” occurs after substantial setup, contrary to the declared first-output requirement.** DESIGN promises `"First job, first printed lines."` But `hires.py` performs all population rollouts, rule refits and target-mesh held-out projections before `"QUICK"`. `hops.refit_weights` accepts `"max_seconds=None"` but never uses it. **Minimal fix:** run one predeclared corrected transfer arm immediately after essential setup, then perform certification/refitting; give expensive setup stages explicit budgets and statuses.

16. **Dense truth is neither guaranteed nor a matched quadrature-isolation experiment for every arm.** `hires.py`: `"if time.perf_counter() - begin > cfg['dense_deadline_seconds']: ... continue"` can omit it; the dense query always uses `"gtol=st['gtol']"`, while deployed comparisons include `1e-3` arms. Thus `"deployed_vs_dense"` can mix solver-tolerance and quadrature effects. **Minimal fix:** require the dense comparisons needed by the headline and match tolerance/solver when claiming to isolate quadrature error.

17. **The lattice’s weight is correct, but its advertised exactness is too broad.** `hops.py`: `"For a product Phi_m a(u) whose combined wavenumber stays below 2s the sine-sum is exact"`. Low trigonometric frequency alone does not ensure this interior quadrature identity: odd sine terms have mesh-dependent sums. For example, `sin³(πx) sin²(πy)` has low finite frequency content but is not generally integrated exactly by this rule. Upwind branch switching further defeats a blanket bandlimit assumption. **Minimal fix:** restrict the exactness statement to the appropriate discrete sine-product orthogonality class; retain empirical certification for advection.

18. **The metric is declared transparently but supports a narrower accuracy claim than “relative L² error” suggests.** DESIGN uses `"||u_k - u_k^tight||_2 / ||u_0||_2"` and scores only `"max_{k≥1}"`. For decaying solutions this can be much smaller than current-state relative error; errors before `t=.05`, including the acknowledged ≈3.9% initial compression, do not affect the success bar. **Minimal fix:** call it *initial-norm-normalized error at sampled evolved times*, report current-state-relative and all-times errors alongside it, and avoid describing it as uniform trajectory accuracy.

19. **There is no direct evaluation-to-NNLS leakage in the shown driver, but development-set selection is not final validation.** `hires.py` fits from `"pops[q]['fit']"`, sourced from `"ph = train_physical[i]"`, and checks training/evaluation disjointness. However, DESIGN selects `"cheapest certified arm with evolved error ≤ 1 %"` on the same six development cases and acknowledges earlier lattice exploration on one development case. Checkpoint/direction training provenance is not established by the supplied code. **Minimal fix:** label results as development selection; freeze the selected arm before opening the sealed final cohort, and document upstream provenance.

20. **`hfast` changes diagnostic semantics while claiming the same tuple contract.** `hfast.py`: `"slot 8/12/14 all carrying the LM's joint exit gradient"`. In `topfix`, slots 8 and 14 are separately normalized z/y gradients. A small joint gradient need not imply either block-normalized gradient is small. **Minimal fix:** preserve the block values or return named diagnostics with unavailable block quantities explicitly marked. Replacing slot 12 with the LM’s joint gradient is mathematically justified.

21. **The analytic Jacobian is algebraically correct, with two necessary qualifications.** `hfast.py`: `"J = jnp.concatenate((data['A'] @ Jh, tab['AC']), axis=1) + (dt * S)[:, None] * (data['Pq'].T @ dA)"`. The unscaled first term is correct because `S(1+dt νλ)=1`; `AC` and `G5C` are valid affine folds. Stencil order matches `CoordBank.stencil` and `arms.weak_eq`. For `c>0`, the stencil derivative is
   `L(4c−xm−ym, 0, −c, 0, −c)`; for `c<0`, it is
   `L(xp+yp−4c, c, 0, c, 0)`.
   At `c=0`, a classical derivative generally does not exist; `dadv` matches JAX’s selected `c>0` branch convention. Also, residual division versus multiplication by `S`, and cancellation in the Jacobian, prevent bitwise equivalence. **Minimal fix:** state “algebraically correct away from switching surfaces, matching AD’s branch convention at zero,” and test against `jacfwd(res)` numerically.

22. **Fused LM matches the supplied block LM algorithm for LU; initialization equivalence is conditional.** `hfast.py`: `"r2, J2 = evalJ(wn, args)"` changes evaluation scheduling, but acceptance, damping, trust, stopping precedence and budget behavior match `varpro.make_block_lm` for matching residual/Jacobian values. Cholesky is a separate numerical factorization. The `q>0` base initializer also matches algebraically, including exact y elimination, provided the hoisted tables match `cold` and `C` and `RC` has full column rank. However, `hfast` uses `"gtol=ic_gtol"` for `q=0`, whereas `topfix` delegates to `varpro`, whose initializer uses evolution `gtol`; defaults therefore differ at `gtol=1e-3`. **Minimal fix:** align the q=0 policy explicitly and gate numerical parity. The omitted `fast.py` implementation cannot be audited here.

23. **Mode ordering, projection scaling, transfer scaling and QR compression pass the algebraic audit.** `hops.py`: `"np.argsort(lam.ravel(), kind='stable')[:M]"` matches `engines.modes`; C-order `(i,j)` flattening and `"return (2. / L) * jnp.sum(sx * (V @ sy), axis=-2)"` reproduce `Phi.T @ v` mathematically, with different floating-point summation. Lattice weights `(L/s)²` and transferred weights `"* (L / part['mesh']) ** 2"` correctly scale the unnormalized grid sum; they do not guarantee transferred accuracy. Finally, `"Dc, bc = Rfull[:m, :m], Rfull[:m, m]"` correctly preserves the NNLS minimizer, and the omitted QR row contributes the constant `tail²` already included in the reported fit. **Minimal fix:** replace claims of exact numerical equality with algebraic equivalence plus toleranced parity; extend the current `M=64` operator gate to all deployed mode counts.
