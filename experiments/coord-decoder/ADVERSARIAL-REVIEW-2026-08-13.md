## Findings

1. **BLOCKER — The stated “rank-\(R\) POD hard floor” is not mathematically established.** The production decoders add a learned scalar bias ([Poisson decoder:45](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/poisson/src/tunable_rom_poisson/models/decoder.py:45), [Heat decoder:37](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/heat/src/tunable_rom_heat/models/decoder.py:37)). Thus the image is contained in an affine rank-\(R\) set \(b\mathbf1+\operatorname{span}\{v_r\}\), not necessarily an \(R\)-dimensional linear subspace as claimed in [ARCHITECTURE.md:59](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/ARCHITECTURE.md:59). Equivalently, it lies in a linear space of dimension at most \(R+1\). There is no output nonlinearity, so the fixed-affine-subspace diagnosis is otherwise valid. More seriously, ordinary SVD is optimal for training-set absolute Frobenius error, while the tables use validation-set mean per-sample relative L2 ([poisson2d_diag.py:222](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/poisson2d_diag.py:222)). Those reported POD values are not certified lower bounds for that validation metric.  
   **Resolution:** Report centered affine POD-\(R\), uncentered POD-\(R+1\), and a relative-error-aligned basis on exactly the evaluation distribution. State the theorem for a specified norm/population rather than identifying train-SVD validation error with a hard floor.

2. **BLOCKER — Poisson’s “monotonic” convergence headline is directly false in both canonical sweeps.** The claimed “never rises” statement is at [README.md:84](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/README.md:84). In `film_convergence_fixed.json`, error rises \(9.786\times10^{-3}\to1.089\times10^{-2}\) from \(N=64\) to \(128\), an 11.3% increase. The 1D artifact `results_convergence.json` likewise rises \(8.848\times10^{-3}\to9.575\times10^{-3}\) from \(N=128\) to \(256\). Calling either curve monotonic or saying it “never rises” is untenable.  
   **Resolution:** Retract “monotonic/never rises,” or repeat every cell across multiple seeds and show a statistically supported trend with confidence intervals. A non-increasing isotonic fit is not a substitute for raw results.

3. **BLOCKER — The convergence studies do not hold architecture or training work fixed across resolution.** Poisson changes `N_FREQ` from 8 to 16 to 32, giving 439,105, 447,297, and 463,681 parameters, while `P=min(8192,N²)` increases per-step point evaluations from 256 to 8,192 ([poisson2d_film.py:45](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/poisson2d_film.py:45), [poisson2d_film.py:232](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/poisson2d_film.py:232)). Heat similarly changes `N_FREQ` 7/15/31/32 and parameters 442,561/450,753/467,137/468,161 ([heat2d_film.py:57](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/heat2d_film.py:57)), contradicting “identical parameter count” at [README.md:72](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/README.md:72). Therefore the falling heat curve cannot be attributed solely to better discretization.  
   **Resolution:** Run a fixed-bandwidth architecture safe at the smallest \(N\), fixed point-evaluation/FLOP budget, and fixed checkpoint rule across all resolutions. Separately ablate bandwidth and sample budget.

4. **BLOCKER — “Online solve cost depends only on \(k\)” overclaims a conditional kernel result.** The measured kernel also depends on EQ cardinality \(m\), decoder rank, width, stencil size, and iteration count. Actual Poisson configurations co-vary these with \(N\): rank 128→768 and minimum EQ points 640→1,280 between the existing 2D configurations. The audit explicitly excludes the \(O(n)\) full decode and full-source construction ([AUDIT.md:35](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-cost-scaling-cp/experiments/cost-scaling-cp/AUDIT.md:35)), yet the figure labels the plotted kernel “one online solve” and titles it “depends only on \(k\)” ([figure_cost_scaling.py:125](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-cost-scaling-cp/experiments/cost-scaling-cp/figure_cost_scaling.py:125)). The coordinate arm does not time full-field decoding at all.  
   **Resolution:** Narrow the claim to: “At fixed \(m,R,H,k\) and iteration count, the hyperreduced GN kernel contains no \(n\)-shaped tensors.” Then time end-to-end parameter-to-output solves, including transfers, source evaluation, iterations to tolerance, and requested field/QoI decoding.

5. **BLOCKER — No artifact demonstrates that the coordinate decoder fixes the actual NM-ROM.** Every accuracy test receives the exact physical family parameters; there is no encoder error, inferred latent state, GN solve, EQ error, or time-stepping stability. Heat’s \(u(x,y,t;z)\) is a supervised parametric solution surrogate, not yet an autonomous nonlinear-manifold ROM. The coordinate timing code uses random weights and a synthetic solver skeleton rather than a trained model. Both READMEs acknowledge this as future integration work.  
   **Resolution:** Put a trained coordinate decoder behind the real Poisson and Heat solvers, infer/solve for latent variables without ground-truth parameter codes, and report accuracy, convergence failures, and end-to-end latency on the production families.

6. **MAJOR — Fixed random-weight ten-iteration timings say nothing about practical solve-to-tolerance cost.** CP forces ten iterations with `gn_rel_tol=0`; coordinate manually dispatches ten separately jitted steps. Required iterations and required \(m\) may depend on mesh accuracy, conditioning, and training. Random weights remove precisely those effects.  
   **Resolution:** Use trained checkpoints, fixed physical accuracy/residual targets, data-selected EQ sets, and record failure rates plus iteration distributions across validation cases and resolutions.

7. **MAJOR — The two timing arms are not comparable in absolute latency.** CP uses the real weighted LM loop with four-way line search and \(m=640\); coordinate uses unweighted normal equations, constant damping, no line search, a Python loop around a jitted step, and \(m=100\) ([time_coordnet_rom.py:110](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-cost-scaling-coordnet/experiments/cost-scaling-coordnet/time_coordnet_rom.py:110)). CP’s FLOPs also include its initial residual/Jacobian overhead divided by ten, while coordinate’s do not.  
   **Resolution:** Implement both decoders behind the same solver interface, GN/LM algorithm, \(m\), line search, compilation boundary, and stopping rule. Until then, remove cross-arm absolute-time conclusions.

8. **MAJOR — The Poisson “grid-tied CP-style” control is a trainability strawman.** Its free matrix has shape `(rank,N²)` ([poisson2d_diag.py:128](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/poisson2d_diag.py:128)), whereas the production CP decoder has two `(rank,N)` factors. The dense control is more expressive, but its \(O(RN²)\) parameter growth and sparse per-node gradients are not the production CP parameterization’s \(O(RN)\) optimization problem. Therefore it supports the subspace limitation, not the claimed production trainability mechanism. Heat is also unequal: 40k grid steps versus 120k FiLM steps, full-grid versus importance-sampled objectives, and no best-validation selection for grid ([heat2d_film.py:48](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/heat2d_film.py:48)).  
   **Resolution:** Train the actual CP decoder with matched compute, loss sampling, and checkpoint selection. Include random, CP/HOSVD-informed, POD-informed dense, frozen-basis, and trainable-basis initializations.

9. **MAJOR — Several POD comparisons are not computed on the same data or metric as the claimed winner.** Poisson FiLM uses 2,048 training cases, while the cited POD-24/64 values come from the earlier 512-case round. Heat POD fits and evaluates only every fourth time slice ([heat2d_film.py:168](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/heat2d_film.py:168)), while neural-arm headline errors average all 51 slices, contradicting [README.md:23](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/README.md:23).  
   **Resolution:** Recompute every POD basis from the exact corresponding training set and evaluate it on the exact same test cases, reference grid, time slices, and metric.

10. **MAJOR — Validation is used for checkpoint selection and headline reporting, with one seed throughout.** Poisson and Heat choose the minimum validation loss over roughly 60 checkpoints and then report that same set ([poisson2d_film.py:224](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/poisson2d_film.py:224), [heat2d_film.py:400](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/heat2d_film.py:400)). The same seed-0 split also informed multiple architecture rounds. Heat’s final “monotonic” improvement from \(N=128\) to 256 is only 0.21%, far below any quantified training variance.  
    **Resolution:** Lock an untouched common test parameter set; use validation only for selection. Run at least 5–10 training/data seeds and report confidence intervals and per-sample quantiles.

11. **MAJOR — The “data floor/discretization bound” is not a lower bound.** It is merely the error of bilinearly interpolating coarse FD solutions ([film_convergence_eval.py:71](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/film_convergence_eval.py:71), [heat2d_convergence_eval.py:97](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/heat2d_convergence_eval.py:97)). A parametric model can learn systematic discretization correction or super-resolution and beat it. The references also use the same FD/CG implementation and, for heat, the same time step, so they validate fine-spatial agreement with that scheme—not continuum PDE accuracy.  
    **Resolution:** Rename it “coarse-interpolation discrepancy.” Establish reference convergence with finer \(N\), Richardson estimates or an independent solver, and for heat a separate \(\Delta t\) refinement.

12. **MAJOR — Heat’s aggregate monotonic mean hides resolution regressions at most reported times.** From \(N=128\) to 256, the mean improves only \(9.551\times10^{-3}\to9.530\times10^{-3}\), while errors worsen at times 20, 30, 40, and 50 by approximately 6.7%, 11.1%, 15.7%, and 13.1%. At \(N=256\), error roughly doubles from time 10 to time 50. This weakens “no drift” and “never rises” at [README.md:44](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/README.md:44).  
    **Resolution:** Report curves and worst-case/quantile errors over every time slice; require convergence per time or state explicitly that only the six-time aggregate is monotone.

13. **MAJOR — The claimed Nyquist threshold is misidentified and not established as universal.** For features \(\sin(\pi jx)\) sampled at spacing \(1/(N-1)\), the ordinary frequency Nyquist condition is \(j\le N-1\), not \(j\le N/2\). The implemented \((N-1)//2\) rule instead roughly prevents the combined sine/cosine feature map from becoming overcomplete on \(N\) samples. The catastrophic off-grid failures do demonstrate non-identifiability/alias risk, but two single-seed configurations do not prove that this exact cap “must” be used.  
    **Resolution:** Call it an identifiability/feature-rank heuristic, analyze the sampled feature matrix, and sweep bandwidth around both thresholds with off-grid validation and regularization.

14. **MAJOR — “Lossless mesh transfer” is unsupported wording, and one key number has no stored artifact.** `transfer2d_eval.py` only prints results and writes no JSON/log ([transfer2d_eval.py:38](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/transfer2d_eval.py:38)); the archived `round2/` directory contains no transfer result. Its docstring says the checkpoints use `N_FREQ=32`, while the script defaults to 16 ([transfer2d_eval.py:3](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/transfer2d_eval.py:3)). The original FiLM checkpoints’ \(10^3\)–\(10^4\) off-grid errors also prove that native evaluation is not inherently lossless.  
    **Resolution:** Archive per-sample transfer results and configuration hashes. Replace “lossless” with “interpolation-free/native-coordinate evaluation,” and quantify the transfer penalty against in-resolution and fine-reference errors.

15. **MAJOR — The GN-tolerance study is not currently usable.** Only a Poisson smoke artifact exists; it has eight cases and `model_rel_l2 ≈ 1.000`, so its iteration counts are not representative. No heat or full-run results exist. Additionally, Heat’s derived count is off by one: with direct `j_first`, the correct count is `j_first+1`, but the code uses `j_first+2` ([measure_gn.py:220](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-gn-tolerance-sweep/experiments/gn-tolerance-sweep/measure_gn.py:220)). More fundamentally, arbitrary heat tolerances cannot be postprocessed from a trajectory whose warm-start chain was generated using only the configured tolerance; changing an earlier stop changes all later histories. It also stores no accuracy at alternative stopping iterates.  
    **Resolution:** Fix the count, rerun a complete rollout separately for each tolerance, and record state error, residual, iterations, failures, and latency using accurate trained checkpoints.

16. **MINOR — “f64 evaluation” is inaccurate.** Both neural models infer with f32 parameters, coordinates, and latent inputs; predictions are merely cast to float64 before computing norms ([poisson2d_film.py:252](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-12-coord-decoder/experiments/coord-decoder/poisson2d_film.py:252), [heat2d_film.py:435](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-13-heat2d-coord-decoder/experiments/heat2d-coord-decoder/heat2d_film.py:435)). This likely does not affect \(10^{-3}\)-level errors, but the description is false.  
    **Resolution:** Say “f32 inference, f64 norm/reference,” or actually evaluate a converted f64 network.

17. **MINOR/MAJOR reporting errors — Stored JSONs contradict several prose claims.** The main table cells otherwise match JSON rounding, but:

    - Heat’s “65,536× more points” is 1,024×: \(512^2/16^2\).
    - Cost README claims coordinate FLOPs are monotone, but JSON gives \(8.38\times10^8\) at \(k=2\) and \(6.20\times10^7\) at \(k=4\), demonstrating another `cost_analysis()` artifact.
    - “Both are 4–6 orders below the FOM” is false. At the plotted \(N=512,k=8\), ten-iteration CP and coordinate kernels are about 1.78 ms and 3.43 ms versus a 31.1 ms FOM: roughly 17× and 9×, not \(10^4\)–\(10^6\).
    - Heat’s “8,192 sampled points per step” is false at \(N=16,32,64\), where the code caps at 256, 1,024, and 4,096.

    **Resolution:** Regenerate every prose claim programmatically from JSON and remove unsupported orders-of-magnitude and sample-count statements.

## Fix first

1. Run a genuinely controlled convergence study: fixed bandwidth, parameters, point/FLOP budget, independent test set, and multiple seeds. This determines whether any monotonic-resolution headline is defensible.
2. Integrate the trained coordinate decoder into the real ROM and measure end-to-end accuracy-to-tolerance cost, including actual \(m,R\), iterations, transfers, and full/QoI decoding.
3. Correct the linear-bound experiment: affine/relative-metric POD on matched data, plus actual CP controls with POD/HOSVD-informed initialization and matched training budgets.

## Overall verdict

The qualitative mathematical diagnosis survives only in weakened form: the production CP decoder is confined to a fixed low-dimensional **affine** set, so it has a genuine linear-width limitation. The reported POD-\(R\) values are not, however, certified hard floors for the metric shown.

The raw coordinate-network errors do beat the reported POD controls by large margins, so the basic nonlinear-representation signal is likely real. The “~7× best-linear,” “lossless transfer,” and especially Poisson “monotonic/never rises” formulations do not survive scrutiny. Heat’s aggregate curve is numerically monotone, but it is confounded by increasing bandwidth, parameters, and training samples and hides per-time regressions.

The timing artifacts prove only that a fixed-shape hyperreduced GN kernel is independent of \(n\). They do not prove that practical online ROM cost depends only on \(k\). As a package, the headline claims are not ready for an advisor or NeurIPS submission without the three fixes above.
