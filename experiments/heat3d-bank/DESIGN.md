Branch `exp/2026-09-21-heat3d-bank` (fork of hires-heat `4fb12a6d`). Cluster namespace `/cluster/tufts/paralab/tawal01/h3dbank_20260921/`.
Protocol: `reports/2026-09-20-speed-accuracy-campaign-protocol.md` (binding).

## Question

Can a wider learned coordinate bank, trained without per-snapshot codes, bring Heat 3D to worst relative $L^2$ error $\le 1\%$
over **all** output times including $t=0$, on the sealed cohort at $128^3$ (also $32^3$, $64^3$), and how fast is it against the named
Crank–Nicolson CG FOM in the same allocation? Current state: $1.93\%$ all-times at $128^3$ (hires-heat `h3d-final08`, paper failures table),
because the frozen $R=128$ bank represents the initial field only to $\approx 1.5$–$1.9\%$.

## Root cause of the previous training failures (hires-heat jobs 4071535, 4072491)

`train.py` (auto-decoder) learned codes $\eta$ with Adam and replaced them every 10k/20k steps by exact least-squares coefficients.
At each refit it zeroed the code Adam moments but kept the **shared step count**, so bias correction was $\approx 1$ and a re-sampled
code row moved $\sim 3$–$30\times$ the learning rate. Local evidence, `diagnostics/refit_smoke.py` (same code, shrunk; sparse row sampling
matched to the cluster run, 1 row in 48 per step; `diagnostics/refit_smoke_bank_batch_states6.json`): full-batch loss 50 steps after the first
refit **0.0448 → 0.1357 (×3.0)** with the original reset; **0.0531** with the code optimiser fully re-initialised (count reset);
**0.0412** (decreasing) when the moments are kept. At scale the kicks compounded with a bank whose condition number grew to $10^8$
(truncated refit kept 112 of 256 directions): 4071535 diverged (loss $4\times10^9$), 4072491 degraded the validation floor $2.3\to 6\%$.

**Fix:** remove the codes entirely. `train_vp.py` eliminates the optimal coefficients exactly for the current bank $G$ (variable
projection), so the loss is the true projection error onto $\mathrm{span}(G)$; nothing can lag or be kicked. Same toy config:
auto-decoder training floor 17–24 % after 3000 steps vs variable-projection **validation** floor 14.8 % (POD reference with the same
48 training draws: 12.4 %).

## Model and training (configs generated by `make_configs.py`)

- Data: training seed 921000, **2048 draws** × 6 times at $32^3$ (training grid); validation seed **921777**, 256 draws (all selection).
- Bank: $G(x) = s\,m(x)\,\mathrm{MLP}(\mathrm{RFF}(x))$, 128 random Fourier features (scale 2.0, fixed), 3 hidden layers of 512 (SiLU),
  output $R\in\{256, 320\}$ (two parallel jobs). Loss (f64, full $31^3$ grid):
  $\log\big(\sum_k w_k\|(I-P_G)v_k\|^2\big) + 0.5\log\big(\mathrm{mean}_b\, e_b^4\big)^{1/4} + 10^{-3}\,\mathrm{mean}((C-I)^2)$,
  $v_k$ = top-1536 POD modes of the normalised training snapshots with weights $\lambda_k/S$ (exact mean training error restricted to
  those modes), $e_b$ = squared projection error of 512 random training snapshots, $C$ = column-cosine matrix of $G$ (span-invariant
  conditioning). Adam, warm-up 500, cosine $10^{-3}\to10^{-5}$, 40k steps, clip 1. Checkpoint = lowest worst validation projection error.
- Head: `train.train_head` unchanged (hires-heat), $K\in\{16, 32\}$, width 512; correction directions = SVD of training head residuals.
- Reference only: optimal (POD) $R$-subspace of the same training data, validation worst floor, logged in `training.json`.

## Pre-registered selection rule (applied mechanically by `select.py` on validation summaries)

1. Bank gate: a model is a candidate only if its bank's validation projection floor at $128^3$ is $\le 0.6\%$.
2. For each candidate $(R,K)$: accurate $q$ = the smallest ladder $q$ whose `field_cn` arm has validation worst all-times same-grid error
   $\le 0.8\%$ at **both** $64^3$ and $128^3$, with zero failed solves.
3. Among candidates with such a $q$: smallest validation median GPU time of that arm at $128^3$; ties within 5 % go to smaller $R$, then smaller $K$.
4. Final arms for the chosen model: $q=0$ (fast), accurate $q$ with `cn` and `direct` stepping, top ladder $q$ (both steppings), and the
   `cn_dt0.05` / `cn_dt0.1` variants of the accurate $q$ if they exist and pass the same 0.8 % validation test.
5. If no candidate reaches 0.8 %: take the lowest validation worst all-times error at $128^3$ (`field_cn`), run the final anyway, report a miss.

## Pass bar and reporting

- Accuracy bar: sealed worst all-times same-grid relative $L^2 \le 1\%$ (stretch $0.5\%$) for the accurate setting, per mesh.
- Speed: $S = T_{\rm FOM}/T_{\rm ROM}$ vs the named CN-CG (dt 0.025, rtol $10^{-6}$) and vs the **fastest tested CN-CG setting whose
  all-times error is $\le$ the ROM's** (paper FOM-selection rule), same allocation, GPU-query scope, medians of 5 repetitions after burn-in.
  Protocol bar $S\ge 5$ vs named. The FOM ladder: dt $\in\{0.025,0.05,0.1\}$ × rtol $\in\{10^{-4},10^{-3},10^{-2}\}$ + named.
- Labelled controls printed beside (not comparators in the paper): linear solve in the learned bank (baseline), exact DST, coarse-grid CN-CG.
- `direct` stepping (exact-propagator targets on eigenfunction tests) is valid only for this linear autonomous PDE; labelled everywhere.
  `cn` stepping is the plain row.

## Controls must fail on real data

- The bank gate and the 0.8 % rule are checked against the old frozen $R=128$ bank's known numbers: its floor ($\approx1.9\%$) fails
  the 0.6 % gate and its $q=96$ ($2.06\%$) fails 0.8 %, so neither threshold is vacuous.
- Audit (`audit.py`): independent SciPy recomputation of every error vector from saved fields; full-field exact where saved.
