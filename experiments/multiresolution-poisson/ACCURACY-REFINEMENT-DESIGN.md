# Controlled Poisson coverage and loss-normalization refinement

This approved development experiment retains the compact current separable
architecture and tests whether additional optimization or broader training
coverage improves its frozen-bank limitation. It is separate from the kernel
pilot and was approved by the coordinator for one bounded training job.

The original checkpoint is an unchanged control. Four continuations start from
exactly its bank and head weights: crossing original training coverage versus expanded coverage with inherited
global normalization versus per-snapshot relative normalization. Expanded
coverage adds newly drawn sources from the identical Gaussian family. All update the coordinate bank, nonlinear head and training-only latent
codes, preserving latent dimension and feature count. Head-only fitting cannot
remove the observed unrestricted-bank projection floor.

## Data and inherited-code audit

`sep_poisson.py` trains on the first `N_TRAIN` snapshots returned by
`ms_parametric.build_snapshots`. Reproduction therefore draws the original
default total count before selecting its training prefix. `sample_params`
generates separate parameter arrays sequentially; changing its draw count
changes the resulting prefix. Persist exact source descriptors and hashes for
all training arms. Descriptors are bookkeeping and source-generation inputs;
they never enter the neural head or online initialization.

`sep_common.train_autodecoder` initializes new weights and codes, so the existing
entry point cannot be used as a continuation. `sep_solvers.train_autodecoder_v2`
adds point subsampling, optional AdamW, EMA selection and code polish, but also
initializes new weights. The explicit continuation driver adapts its
point-sampling pattern and crosses the original global relative-MSE with
per-snapshot relative-MSE, retaining feature-Gram regularization. All inherited parameters except `out_scale` receive gradients,
including the Fourier matrix `B`; comments describing fixed frequencies do not
override the actual inherited gradient path. Keep that behavior equal in all
continuations. No old encoder, quadrature-fitting or historical evaluation entry
point is invoked.

Training truth is regenerated by the validated discrete DST solver on the
checkpoint's original node mesh. It solves the same constant-coefficient finite
difference equation used by the inherited CG snapshots; a small parity check
against tight CG accompanies regeneration. Neither reference manufacturing nor
oracle fitting supplies an online initialization.

## Frozen approved budget

The implemented machine-readable budget is `config04.json`, based on the approved
`accuracy_refinement_proposal.json`. It fixes
matched optimizer updates and sample/point batches, the same reset Adam state,
the same learning-rate schedule, the original objective weights, and no EMA or
weight decay. The global field-scale denominator is computed from the original
training set and shared by both global-loss coverage arms to hold loss scaling fixed. The relative-loss arms
use each field's full-grid mean square as a fixed denominator, never a stochastic
point-sample denominator. This tests whether global loss underweights low-energy,
narrow fields; it is a hypothesis, not a conclusion. Feature-Gram regularization
keeps its original coefficient in every arm. Original codes
come from the checkpoint. New training codes use a fixed-budget reference-only
head fit once before all training arms; its cost and failures are recorded as
offline setup. Initialization uses training answers only.

For a full training field $u_i$, let $d_i$ be its full-grid mean square and $d_0$
the global mean square on the original training set. The two reconstruction
losses are

$$L_{\mathrm{global}}=\frac{\operatorname{mean}_{i,x}
|u_\theta(z_i,x)-u_i(x)|^2}{d_0},\qquad
L_{\mathrm{relative}}=\operatorname{mean}_i
\frac{\operatorname{mean}_x|u_\theta(z_i,x)-u_i(x)|^2}{d_i}.$$

Both add the same feature-Gram penalty. Source and point indices are sampled
uniformly with replacement, giving unbiased estimates of their declared losses.
The random-key schedule is identical across arms; coverage pairs share exact
source/point choices across objectives. New-code initialization retains every
termination and gradient diagnostic; a nonfinite fit falls back to the original
mean code, with that event recorded. Finite nonstationary initial fits remain
labeled as such and are subsequently optimized during training.

Each expanded arm samples uniformly from its union. Thus the budget matches
compute rather than per-example passes; original examples receive fewer updates
in the larger set. Identical coverage arms share source/code initialization across
the two objectives. This is explicitly a fixed-compute coverage comparison,
without a claim that any continuation converged. Save optimizer progress and
the final checkpoint for each arm; if the wall limit truncates an arm, retain it
as truncated and do not silently compare unequal update counts.

## Evaluation and interpretation

Retain the existing development sources for continuity and add a separately
seeded small development validation group for diagnosis, with all descriptors
frozen before training. Neither group chooses training steps or weights. Report
the final scheduled checkpoint, including regressions; there is no best-of-step
selection. Sealed final cohorts remain closed.

For all five checkpoints, rebuild the bank and weak operators on both query
meshes. Report actual bank rank, unrestricted full-bank error, stationary
multistart head fits and the enlarged-test weak solve. Compare common-observation
physical discrepancy with independently refined references, keeping the
empirical reference qualification explicit. Test-space size, solve budget and
initialization rules are identical across checkpoints. The online initial code
is the mean of that checkpoint's training codes; the reference-only head fits
never supply it.

Complete-query measurements use full host source input, full host field output,
the original solver control, the validated specialized kernel if qualified, and
efficient DST in the same GPU job. Persist every invocation and component cost.
Offline data, initialization, training, operator setup and compilation costs
remain separate, permitting later amortization analysis. Bank improvement with
matched compute supports a coverage/optimization effect within this architecture;
failure leaves capacity or objective design open rather than establishing an
irreducible floor for the model family.

## Plain-language glossary

- **Continuation / checkpoint:** additional training from existing weights / saved
  weights and training latent codes.
- **Bank / head / latent code:** coordinate-dependent spatial features / nonlinear
  map to their coefficients / compact coordinates fitted for each training field.
- **Coverage / prefix / cohort:** range of sampled sources / leading subset of a
  fixed draw / a persisted group of sources.
- **DST / CG:** direct sine-transform solve / conjugate-gradient iterative solve
  of the same finite-difference equation.
- **Adam / EMA / global relative MSE:** adaptive gradient optimizer / moving average
  of weights / mean squared field discrepancy divided by one field-scale constant.
- **Feature Gram / point sampling:** feature inner-product regularizer / training
  using a subset of spatial nodes per update.
- **Oracle / stationary:** diagnostic fit allowed to see an answer / locally small
  normalized objective gradient, without proof of global optimality.
- **Fixed compute / amortization:** equal update and batch budgets / spreading
  offline cost across later queries.
