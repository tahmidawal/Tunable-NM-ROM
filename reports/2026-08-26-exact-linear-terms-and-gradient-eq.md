# Exact linear terms, gradient-target quadrature, and learned nodes

What happened when the weak residual's linear terms were made exact (no quadrature), the
freed node budget was refit for the advection term against what the solver actually
consumes, and finally the node positions themselves were learned. Follow-up to
`2026-08-25-eq-fidelity-ladder.md` (its §3 fix ranking, items 1–3) and the advisor's
"learn the quadrature" ask (meeting notes 2026-08-25). **Status: all numbers final** (14 cluster
arms, jobs 2844813–2844912, all pulled, verified, and deleted from the cluster).
Branch `exp/2026-08-26-eq-learned`; every table below is generated by
`reports/gen_2026-08-26-exlin.py` from the run JSONs — nothing is typed by hand.

## 1. What changed in the residual (stage 1)

The separable decoder makes every `Φᵀu` term exactly computable: with `A = ΦᵀG_int`
(an M×R matrix, precomputed once offline), the online residual becomes

```
r_w(z) = wt ⊙ [ A(h(z) − h(zⁿ)) + Δt·( Φ_qᵀ N(u)|nodes + ν λ ⊙ A h(z) ) ]
```

Mass, previous-state and Laplacian terms need **no quadrature at all**; only the
advection term `ΦᵀN(u)` (sign-upwind, quadratic in u) stays on the m NNLS nodes. The
m nodes are then refit on **advection rows only** — the freed budget serves one term.
`A h(z)` is an M×R matvec (M ≤ 256, R = 512), so the online cost is unchanged, and
T-X1 confirms that with paired timings.

**Gate rule change (deliberate, announced in the 08-25 report §3 item 1).** Gate 0 —
bit-identity of the whole sampled residual to `make_weak_ops` — cannot apply to the
exact-linear residual *by design*: the linear part is now a different (exact)
computation. It still runs on incumbent-form ops built on the same node set (code
identity), and two new gates cover the change: **gate L** (exact-linear part vs
full-grid linear part, ≤1e-12; measured ≤3.4e-15 everywhere including N=1024) and
**gate A** (sampled advection part vs the incumbent's advection evaluation, ≤1e-12;
measured ≤5.5e-14, mostly exactly 0). Gate F (full-grid reference vs `make_weak_ops`
on the whole interior, N≤512) is unchanged. T-X5 lists every measured gate.

## 2. Stage-1 findings (final)

- **F1 — Accuracy improves at zero cost.** On the round-4/5 matched-accuracy protocol
  (same checkpoints, same GPU types as the incumbent runs): rollout error
  9.69e-3 → 7.98e-3 (−18%) at N=1024 and 8.96e-3 → 8.02e-3 (−11%) at N=256, while the
  paired speedup is unchanged (1.90× → 1.87×, 0.37× → 0.36×, within run-to-run noise).
  T-X1.
- **F2 — The residual error is now purely advection, and smaller.** `b_lin` collapses
  to ~1e-13 (zero by construction) on every checkpoint; total (b) on the fine set
  (m=1024) improves 1.9–3.3× on the solver path and up to 4.8× at the oracle
  (dense_mid oracle (b) 0.14 → 0.029). Oracle gradient cosines are now 0.90–0.99 on
  all four checkpoints. T-X2.
- **F3 — Coarse-set rollouts improve 7–20%; fine-set rollouts do not move.** At m=256
  every checkpoint's rollout error drops (e.g. r4a6 3.03e-2 → 2.47e-2); at m=1024 it
  is unchanged to three digits on all four checkpoints. At the fine budget the
  quadrature was already not the binding error for these checkpoints — consistent with
  the lab-log finding that `h`'s generalisation is the binding rung. Quadrature fixes
  help exactly where quadrature was the limiter.

## 3. Stage-2 findings — same-target NNLS (four quadratures at fixed m)

Four node/weight sets, all run online with the exact-linear residual, certified by the
ladder on **held-out** solver iterates (collected from training-trajectory rollouts,
excluded from every row build), on the test solver path, at oracle states, and by test
rollouts (T-X3):

- **F4 — Where the rows are evaluated matters more than what they weight.** Moving the
  advection rows from training *codes* to off-manifold *LM iterates* (set `path`) is
  worth ~2.5× on held-out (b) and takes the held-out gradient cosine from ~0.46 to
  ~0.90 (N=1024 m=256). The frozen-Jacobian gradient rows (`grad`) add another ~1.6×
  on held-out (c1) (cos 0.95).
- **F5 — The gains reach the rollout only at the coarse budget, and are
  checkpoint-dependent.** N=1024 K=32 at m=256: rollout error is monotone in row
  quality, inc 2.61e-2 → adv 2.47e-2 → path 2.19e-2 → grad 2.07e-2 (−21% vs the
  incumbent set). But N=256 dense_mid at m=256 shows NEGATIVE transfer: inc 1.52e-2 /
  adv 1.51e-2 / path 1.71e-2 / grad 1.71e-2 (+13%) — the same-target sets overfit the
  fit-state distribution on that checkpoint (test-path (b) degrades 0.21→0.39 while
  held-out still improves). At the fine budget (m=1024) all four sets tie on rollout at
  both N (1.433–1.440e-2 and 1.102–1.106e-2): where quadrature does not bind, no refit
  can win. A same-target refit must be validated per checkpoint on rollouts before
  adoption.
- **F6 — A quadrature generalisation gap exists.** Held-out fidelity (same state
  distribution as the fit) improves far more than test-solver-path fidelity
  ((b) 0.39→0.15 held-out but only 0.39→0.34 on the test path at N=1024 m=256): the
  fit-side iterate distribution does not fully cover where the solver goes on unseen
  trajectories. This bounds how much any state-conditioned refit — convex or learned —
  can transfer, and is the mechanism behind F5's checkpoint dependence.

## 4. Stage-3 findings — learned continuous nodes

Node positions as continuous trainable parameters (sigmoid box reparameterisation,
min-separation penalty, fixed cardinality m), weights re-solved by the inner NNLS at
the current nodes (variable projection), FROZEN decoder and FROZEN full-grid teacher,
loss = the ladder rungs (b) + (c1, frozen-J_f form) over the same fit states as
stage 2. The upwind `where(c>0)` switch is piecewise in the node position; its
subgradient is used as-is. Gate C (continuous machinery at grid init ≡ grid ops,
≤1e-12) held on every run. T-X4.

- **F7 — Learned nodes beat the convex baseline exactly where quadrature binds, and
  only there (final).** At the coarse budget (m=256) the learned nodes beat `grad` on
  every certification axis on BOTH checkpoints — N=1024 K=32: held-out (b) 0.146→0.071
  (−51%), (c3) cos 0.906→0.985, test-path (b) 0.338→0.262, oracle (b) 0.77→0.53,
  rollout 2.067e-2→2.005e-2 (nodes moved ~7 grid spacings on average); N=256: held-out
  (b) 0.051→0.017, rollout 1.706e-2→1.591e-2. The success bar (beat `grad` on held-out
  (c1)/(c3) AND rollout at the same m) is met on both coarse arms. Two qualifications:
  on N=256 the plain `adv` set still has the best rollout of all (1.505e-2), i.e. node
  learning recovers only part of the same-target family's negative transfer there; and
  at the fine budget (m=1024) node learning is a clean REPORTABLE NEGATIVE on both
  checkpoints — the initialization (the `grad` set) already sits at a loss 3 orders of
  magnitude below the coarse arms', the optimizer only wanders or overfits
  (nf1024m256's final refit loss is *worse* than its init), the learned set certifies
  worse than both baselines, and rollouts are tied. Where quadrature is not the
  binding error there is nothing for learned nodes to win.
- **F8 — Answer to "should the model learn the quadrature".** Learning node positions
  can beat every convex fit on every fidelity rung — but only at coarse node budgets,
  the rollout gain there is small (−3% vs `grad`, −19% vs `adv` at N=1024), transfer
  is bounded by F6's distribution gap, and at the budgets actually used for the
  headline results the quadrature is not the limiter at all (`h`'s generalisation is).
  The zero-cost, always-safe win is stage 1; everything beyond it is situational.

## 5. What this changes about the published numbers

Nothing is retracted. The incumbent-residual results stand as measured; the exact-linear
residual is a strictly-better drop-in whose gains are largest at the coarse node budget
and at coarse-set rollouts, and zero at fine-set rollouts. The NNLS "rel fit" remains a
non-certificate (its advection-only variant reads ~5e-3 while the solver-path (b) is
tens of percent); the ladder remains the only certification used here.
