Overall: the decoder and online NM-ROM solves are real. I found no POD substitution, test-truth leakage, or cached-operator substitution. However, the experiment is not “free of cheats” under the project’s measurement rules: the Burgers timing excludes the required online IC fit, uses an over-solved FOM, discards raw timing repetitions, and falsely claims cost and error came from the same invocation. The advertised 3.3× is therefore not an end-to-end or strong-baseline speedup.

## 1. Nonlinearity — PASS

The model is explicitly

\[
u(x;z)=G(x)h(z),
\]

with a SiLU MLP plus linear skip in `h`; see [sep_common.py:84](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/separable-decoder/sep_common.py:84) and [sep_common.py:105](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/separable-decoder/sep_common.py:105).

Independent f64/highest GPU checks on every committed checkpoint:

| checkpoint | relative superposition failure | Jacobian variation | rank of three tangent spaces |
|---|---:|---:|---:|
| Poisson K=8 | 0.696 | 0.754–0.963 | 24/24 |
| Poisson K=16 | 0.307 | 0.375–0.638 | 48/48 |

The superposition coefficients were `a=0.37`, `b=0.63`, so `a+b=1`; an affine bias cannot manufacture this failure. Each individual Jacobian also had full latent rank. The union ranks exceeding `k` show changing tangent subspaces, not merely a nonlinear reparameterization of one fixed `k`-dimensional linear manifold.

Additional evidence:

- Checkpoint trees contain only `B`, `g`, `h`, `h_lin`, and `out_scale`; no basis or POD coefficients.
- Grepping all `sep_*` drivers found no SVD, eigendecomposition, POD-basis construction, or POD call.
- `g`, `h`, and `h_lin` are randomly initialized and jointly optimized with the per-snapshot codes at [sep_common.py:135](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/separable-decoder/sep_common.py:135). Relative parameter changes from the exact seeded initialization were approximately:

  - `g`: 0.69–0.86
  - `h`: 0.52–0.75
  - `h_lin`: 0.14–0.29
  - `B`: 0.068–0.111

One documentation error: README calls `B` fixed at [README.md:37](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/separable-decoder/README.md:37), but `B` is inside the optimized parameter tree and demonstrably trained. This does not undermine nonlinearity, but the prose is false.

The manifold is nonlinear but remains embedded in the learned `r`-dimensional linear spatial span of `g`. It is not POD, but it is a nonlinear coefficient manifold inside a learned separable basis.

## 4. Timing — FAIL

Several positive checks pass:

- `rollout_jit` really performs a 50-element `lax.scan`; see [blat_common.py:775](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/burgers2d-rom-latent-stepping/blat_common.py:775).
- It uses the same absolute tolerance formula as the untimed rollout.
- Independent comparison gave `(50,16)` latent output, 304 versus 304 Jacobian evaluations, identical 50 stopping reasons, and only `3.1e-10` maximum latent disagreement.
- Both ROM and FOM calls block before stopping the timer.
- Both use two warmups and a seven-repetition median in the same H200 job.

But the timing claims fail the required methodology:

1. **Cost and error do not come from the same invocation.** Poisson obtains error/counters from one `pipe` call and times seven later calls at [sep_poisson.py:179](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/separable-decoder/sep_poisson.py:179). Burgers obtains error/counters from `bc.rollout` and times a separate `rollout_jit` at [sep_burgers.py:193](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-22-separable-decoder/experiments/separable-decoder/sep_burgers.py:193). README and EXPERIMENT explicitly claim otherwise.

2. **The online Burgers IC fit is entirely excluded.** It is required to obtain `z0` from known `u0`, but timing starts afterward. A warmed local K=16 repetition took 7.97 seconds for the nine prescribed starts. That cannot be numerically transferred to the H200, but it proves the reported 54 ms is latent time stepping only, not an end-to-end online solve.

3. **Output work is asymmetric.** The timed ROM returns only latent states (`rollout_jit(...)[0]`), while the timed FOM returns all 51 full-grid states. Cached full decoding was negligible in my local test, but it remains an accounting asymmetry.

4. **Raw timing repetitions are discarded.** Every `med, _ = time_fn(...)` throws away the seven measurements. Poisson retains per-source medians; Burgers retains per-trajectory medians; the FOM retains only one aggregate scalar. Outlier counts and repetition-level reanalysis are impossible.

5. **No balanced timing schedule.** Meshfree always precedes cached, and FOM is last. Burgers has no explicit clock burn; it relies on two warmups. There is no AB/BA or cyclic order.

6. **The Burgers baseline is intentionally over-solved.** It performs a fixed eight Newton iterations per each of 50 steps at [burgers2d_film.py:126](/home/tahmid/Dev/pod-ae-nmrom/Tunable-NM-ROM-Claude/worktrees/2026-08-14-burgers2d-coord-rom/experiments/burgers2d-coord-rom/burgers2d_film.py:126). It is the truth generator, not the optimized cubic/inexact-Newton incumbent. README correctly admits this caveat.

7. **The solvers do not meet the named targets.** Every K=16 Poisson `tau=1e-3` case is censored. Every reported Burgers step stops as `stalled`, not tolerance-reached.

8. Poisson’s source-to-`f_m` projection is also performed outside the timed `pipe`, even though it is an online ROM-specific operation if the source arrives on the grid.

Thus the 3.258× number is a descriptive comparison of partial ROM stepping against an over-solved truth generator—not a supported online or matched-accuracy speedup.

- Poisson test samples are disjoint from training but are indices from the same seed-0 draw and distribution. This is not training leakage, but it is a held-out validation-style cohort, not an untouched-seed confirmation. It could be model-selection contaminated if architecture choices were informed by earlier results on that same cohort.

## Overall verdict

- Real nonlinear decoder: **yes**.
- Real online nonlinear-manifold ROM solve: **yes**.
- No truth leak or POD substitution: **yes**.
- Free of experimental cheats: **no**.

Caveats that must accompany any claim, ranked by severity:

1. Burgers 54.1 ms excludes the mandatory online IC latent fit; it is not end-to-end.
2. The 176.1 ms comparator is a fixed-eight-Newton truth generator, not the optimized matched-accuracy FOM.
3. All Burgers steps stalled, and Poisson K=16 at `tau=1e-3` is 100% censored.
4. Cost/error are separate invocations, raw repetitions were discarded, and timing order was unbalanced.
5. Timed ROM returns latents while timed FOM returns full fields; Poisson source projection is uncharged.
6. Burgers has only four test trajectories, one of which has a 36% IC error.
7. Poisson uses a same-seed held-out cohort rather than fresh-seed confirmation.
8. Gate 0 validates caching identity, not full-grid/EQ fidelity.
9. Results cover only N=64, seed 0, and one H200 job.
10. README incorrectly describes the Fourier matrix as fixed.

I found methodological overstatement and invalid performance accounting, but no evidence that the nonlinear model, PDE solves, checkpoint contents, or error fields were fabricated.
