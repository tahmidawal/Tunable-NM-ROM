The reused cohorts are clearly labelled descriptive, and the same-job requirement is explicit. The following gaps still affect the principal conclusions. References below are to DESIGN.md.

1. **BLOCKER — “Plateau” is guaranteed without convergence (§§5–6).** Every family’s last rung satisfies its own plateau definition, even if accuracy is still changing rapidly. Neither designated `conv` anchor has an acceptance gate. October’s 3D design required eligible `lat32768` and `gl32` rollouts to agree within $10^{-3}$; October’s 2D continuum check used substantially larger Gauss rules. **Fix:** distinguish “within 5% of the largest tested rung” from a demonstrated plateau. Require independent anchor agreement and a predeclared tail-stability check; otherwise report “unresolved” and withhold dependent crossover/selection claims.

2. **BLOCKER — Timed queries deliver different products (§8, lines 138–140).** ROM timing includes six full-mesh fields; FOM timing returns six scoring-lattice fields. The inherited runners confirm this distinction. Coarse/spectral FOMs also receive prepared inputs, whose preparation is outside their timers. These are not equivalent query contracts. **Fix:** choose one common input/output contract and time all required conversions. Report full-field and lattice-output contracts separately if both matter. Define cached model/rule preparation, input transfer, projection/cold start, and decoding explicitly. Inherited 3D projection remains grid-dependent; “off-mesh” does not make the whole query mesh-independent.

3. **MAJOR — Cheapest-rule selection and accuracy matching use inconsistent targets (§7).** “Its $M^*$” could mean family-relative or global, ST or S. Family-relative plateaus can have different errors. The accuracy-matched FOM is qualified against `conv`, whereas the timed ROM is a selected rule allowed to differ from it by 5%. **Fix:** specify the primary selection as ST/global, require a validated anchor, and qualify the FOM against the actual selected ROM’s $W,T$. Define ties, empty candidate sets, and withholding when timing is provisional. Report the selected pair’s achieved errors beside its speed-up.

4. **MAJOR — Failed rungs and cases lack fixed aggregation semantics (§§5–7, G-fin/G-fom).** Excluding an arm can silently remove a large rung from the “every larger rung” condition. Configuration exclusion is also ambiguous when only one FOM case fails. ROM finiteness permits finite solver failures: 2D damping/budget exits remain admissible; 3D reason 0 explicitly means non-stationary. October’s 3D selection limited non-stationary steps to 1%. **Fix:** freeze reference-eligible case sets independently of solver outcomes. Treat failed required rungs as breaking the suffix condition. Require FOM convergence across the complete comparison cohort. Reinstate an explicit ROM solver-quality threshold or label the result as a fixed-work algorithm plateau rather than a converged reduced-solve plateau.

5. **MAJOR — Reference uncertainty can change boundary decisions (§6, lines 101–102; §7).** Being small relative to the entire 5% band does not prevent uncertainty from moving a rung lying near its boundary. Exact FOM/ROM inequality tests are likewise unresolved near equality. **Fix:** propagate per-case reference uncertainty into the aggregate comparisons; report threshold decisions and crossover brackets as unresolved when uncertainty overlaps the boundary. Predefine multiple crossings, no crossing, and non-monotone mesh behavior.

6. **MAJOR — Several gates do not constrain conclusions (§9).** G-par failure merely triggers “investigate” and marked numbers, leaving parity failures publishable without a fixed disposition. G-ctl is an empirical bad-rule expectation, not an injected validation test; it need not exceed twice the new ST plateau. The design also omits October’s injected swapped-case/perturbed-record checks. **Fix:** make unexplained parity failures withhold affected conclusions; distinguish empirical controls from integrity gates; restore fault injections and specify exactly which claims each failure blocks.

7. **MAJOR — Timing selection remains vulnerable to noise (§8).** The fastest of many candidates is selected using only three repetitions on eight cases. Those cases need not represent cohort difficulty. Rep-2/rep-0 drift can miss an anomalous middle repetition. Subtracting median decode time from median fused-query time is not a measured solver duration. **Fix:** preregister the timing subset rationale, use paired per-case summaries with variability and outlier counts, and independently remeasure selected candidates within the same job. Check all repetition blocks. Label subtraction as an operational estimate.

8. **MAJOR — Completion within four GPU-hours is unsupported (§10).** The stated per-mesh ranges already sum to 1.45–4.5 GPU-hours, before failures. Expanded ladders, all-case FOM solves, compilation/warmups, and repeated same-mesh FOM timing require an explicit accounting. In-job CBC/Korobov searches also consume allocated time. **Fix:** provide a component budget and deterministic priority order for remaining meshes/arms, with bounded development pilots. Precompute rule arrays where possible. The submission guard must reserve limits for all concurrently outstanding jobs.

9. **MAJOR — Operator rule conflict needs explicit resolution (§2).** Both inherited off-mesh implementations integrate continuum derivative advection, whereas AGENTS.md requires FOM-exact upwind advection inside the weak term. This is weak projection, so it is not the prohibited strong-collocation method; nevertheless the operator differs. **Fix:** document the governing exception/authorization and describe the continuum-versus-upwind discrepancy explicitly.
