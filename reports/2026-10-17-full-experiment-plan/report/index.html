The experiment plan, simply

What we need to show for the JCP paper, and how · 17 October 2026

In one sentence: show that our reduced model's cost and accuracy depend on its own size (k) and not on the mesh size; that it holds up against other methods; and that it works beyond one test problem.

What we want to show

  1. Cost depends on k, not on the mesh. Making the mesh bigger shouldn't make our solve slower; making k bigger should, in a predictable way.
  2. Accuracy depends on k, not on the mesh. And bigger k should help, up to a point.
  3. We're faster than the full simulation at the same accuracy, at least on large meshes.
  4. We're as good as, or better than, standard reduced models (POD with DEIM, ECSW or GNAT).
  5. It works beyond one problem: other settings, other equations, 2D and 3D.

Each of these is set up so it can fail. We already know two things that fail the strong version: in 2D the biggest bank (512) is slightly worse than 384, and some hard 3D cases still have 4–7 % error. We report those, not hide them.

Step 1: the first small batch (≤ 20 GPU-hours)

Uses only what we already have. No new training, no new equations.

  1. Time each part of the solver as k grows (k from 32 to 512 in 2D, 64 to 1024 in 3D). This shows exactly how cost scales with k. This is the advisor's question.
  2. Time the solve on three mesh sizes (256², 1024², 4096²) for k = 128, 256 and 384. This shows the cost stays flat as the mesh grows.
  3. Check accuracy on the same settings, against our trustworthy reference solutions.
  4. Check every setting is numerically sound first: the solver converged, and there are enough quadrature points. Anything that fails is reported, not used.
  5. A quick recheck of an earlier result (see the note below).
  6. Record memory use and the one-time setup cost.

A small test run first measures what each job really costs, so we don't go over 20 hours. If we run out, we drop the least important items first, and say so.

Something the review caught. In 2D, the set of test functions the model uses changes slightly with the mesh, once there are more than about 1,000 of them. In the accurate setting, 4 of 1,536 differ between meshes. So our earlier "accuracy is flat across meshes" result compared slightly different setups. The effect is probably tiny, but we'll measure it in step 1, and from now on we fix the same set for every mesh.

The ground rules

  • Choose settings only on practice cases. The held-back test cases stay closed until the very end.
  • Score everything against the new trustworthy references.
  • Only settings that pass the "numerically sound" checks go into headline results.
  • Time things fairly: same GPU, same job, side by side.
  • Every claim gets a clear pass/fail rule, written down before we look at results.
  • Codex checks each step before it runs.

Time and cost

Roughly 380–700 GPU-hours for steps 1–4 and the final run, about 4–10 days of GPU time on 3–4 GPUs. Calendar time is longer, because of coding and checks. New equations are extra.

Decisions for you

  1. Which "k" does your advisor mean? The bank size (what we assumed), or the size of the small nonlinear "head" network?
  2. Are new equations in this paper, or saved for later?
  3. Who holds the key to the held-back test cases?
  4. Merge the finished branches? And authorship with Hari.
