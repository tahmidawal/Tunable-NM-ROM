# Learned quadrature nodes at the m=M budget: the win transfers, the speed story does not

This report covers the cluster follow-up to the co-design mini-pilot
(`2026-08-26-codesign-minipilot.md`): frozen-decoder node learning at the tight
quadrature budget, re-run on the real meshes N=256 and N=1024. Numbers are
**final for these checkpoints** (one trained decoder per mesh, one seed, 4 test
trajectories per cell); tables are generated by
`gen_2026-08-27-nodes-mM-transfer.py` from the run JSONs.

## The question

The pilot's F3 finding: at N=64, with the decoder completely frozen, letting
gradient descent move the m quadrature nodes (weights re-solved by NNLS as they
move) cut test rollout error by 17.3% at the binding budget $m = M = 64$, and
did nothing at the generous budget $m = 4M = 256$. Two questions for the real
meshes:

1. **Transfer** — does the in-budget win survive at N=256 and N=1024?
2. **Matched accuracy** — do learned $m{=}M$ nodes *reach the accuracy of the
   NNLS $m{=}4M$ baseline*? If yes, the sampled part of the online solve
   shrinks 4× at no accuracy cost — a direct speed multiplier.

## What was run

Four Tufts jobs (namespace `codesign-mm/`, one directory each; branch
`exp/2026-08-27-nodes-mm`), each certifying the NNLS-grid-node baseline
("base") and the learned-node variant ("cot") with the same instrument:

- `sep_codesign.py`, arm **n**: `TRAIN_H=0 TRAIN_NODES=1 SAMP_REL=1 JAC_REL=1`,
  2000 steps, `LR_NODES=3e-3`, NNLS refit every 500 steps — the pilot driver
  and hyperparameters unchanged (one addition: `TEACHER_CHUNK`, memory-only,
  see Ops).
- Checkpoints from the same trainer family as the pilot's:
  `sep_burgers_N256_K16_R64.pkl` and `sep_burgers_N1024_K16_R64.pkl`
  (the N=1024 draw is 96+8 trajectories / 2048 snapshots, reproduced in-job;
  gate R passed at 1.894e-2).
- Jobs 2956403/2956404 (N=256, A100, ~5 min each) and 2956820/2956822
  (N=1024, H200, first pair 2956408/09 OOMed — retracted, nothing measured).
  All gates (H/R/0/C/D/L) passed in all four completed jobs;
  `jax_backend=gpu` confirmed.

## Findings

**F1 — the in-budget win transfers, shrinking with mesh size.** At $m{=}M$,
learned nodes beat the NNLS baseline at every mesh: −17.3% (N=64), −14.6%
(N=256), −7.2% (N=1024). At $m{=}4M$ the result is a tie at every mesh
(+0.4%, +0.9%, −0.2%) — node learning pays only where the quadrature binds,
exactly as in the pilot.

**F2 — the matched-accuracy hypothesis is refuted.** Learned $m{=}M$ nodes
never reach the NNLS $m{=}4M$ baseline: +13.4% (N=64), +28.1% (N=256),
+11.7% (N=1024) worse (T-N2). **There is no 4×-cheaper-solve-at-matched-
accuracy story.** Learned nodes improve the ROM you can afford; they do not
substitute for a bigger node budget.

**F3 — mismatch improves far more than rollouts, again.** The held-out
gradient rung (c1) improves 3.5–4.2× at $m{=}M$ (e.g. 15.71 → 3.76 at
N=1024) while rollout error improves only 7–17% — the same
decoder-error-dominance shape the pilot measured. The quadrature error that
node learning removes is real but is not the whole rollout budget.

**F4 — the frozen decoder guarantee held everywhere.** Held-out
reconstruction is bit-identical between base and learned-node arms at every
cell (the decoder is untouched by construction); no tripwire fired. Note the
N=1024 baseline is much weaker overall (rollout 1.411e-1 vs 7.2e-2 at
N=256, with *better* reconstruction, 1.724e-2): that checkpoint was trained
on 2048 snapshots vs 8192, and its solve error is dominated by things node
learning cannot touch.

## Interpretation — where the win goes as N grows

(Interpretation, not measurement.) The $m{=}M$ win decays 17% → 15% → 7% as
the mesh refines while m stays fixed at 64. Two readings, compatible: (a) at
N=1024 the non-quadrature error sources (IC fit, decoder solve error — the
weak 2048-snapshot checkpoint) are a larger fraction of the budget, so the
removable quadrature share is smaller; (b) 64 movable nodes on a
$1022^2$-point grid can reshape the sampled operator less, relative to what
NNLS support selection already found, than on a $62^2$ grid. Distinguishing
them would need a stronger N=1024 checkpoint (more snapshots) — which is the
`h`-generalisation lead, not a quadrature lead.

## Recommendation

- **Adopt learned nodes when running at $m{=}M$** — a free 7–15% on the real
  meshes, no decoder risk (reconstruction provably untouched).
- **Do not adopt $m{=}M$ + learned nodes as a speed recipe**: NNLS $m{=}4M$
  is still strictly more accurate. The F3 lead from the pilot is now closed
  both ways: co-training the decoder is a negative (pilot), and node-only
  learning does not close the budget gap (this report).
- The binding lead for rollout accuracy remains `h` generalisation, not the
  quadrature.

## Ops record

The first N=1024 pair (jobs 2956408/09) died on GPU OOM: the vmapped
`jacfwd` of the full-grid teacher materializes an $(S, K, n)$ tangent block —
$128 \times 16 \times 1{,}044{,}484$ in f64 = 15.9 GiB — fatal even on an
H200. Fixed by `TEACHER_CHUNK` (chunked `lax.map`, memory-only: arm n never
differentiates through the teacher), validated at N=64 where it reproduces
the pilot's certification numbers exactly. Failed logs are kept at
`runs/cdmm/failed-oom-logs/` on the branch. All results and logs pulled,
checksums verified, and the cluster namespace deleted.

## Glossary — every term and table column, in plain language

- **FOM / ROM** — full-order model (the PDE solved on the whole grid; the
  expensive truth) / reduced-order model (the cheap surrogate that evolves a
  small latent vector and decodes it to the grid).
- **Decoder** — the trained neural network mapping a latent vector
  $z \in \mathbb{R}^{16}$ to a full flow field. Frozen throughout this
  experiment.
- **m vs M** — $M$ is the number of test functions in the weak-form residual
  (64 here); $m$ is the number of grid points the ROM actually samples to
  approximate that residual. $m{=}M{=}64$ is the tight budget, $m{=}4M{=}256$
  the generous one.
- **NNLS (grid nodes / baseline)** — non-negative least squares: the standard
  way to pick the $m$ sample points and their weights, from grid points, by a
  least-squares fit. "base" rows use these.
- **Learned nodes ("cot" rows)** — starting from the NNLS points, gradient
  descent slides the points continuously around the domain (weights re-solved
  by NNLS every 500 steps) to make the sampled residual match the exact
  full-grid residual.
- **Rollout err** — the number that decides everything: mean relative error of
  the ROM trajectory against the FOM truth over 50 time steps, averaged over
  4 fresh test trajectories never seen in any fit.
- **Held (b)** — relative error of the sampled residual vs the exact
  full-grid residual, on held-out states excluded from every fit. 1.0 means
  the sampled residual is ~100% wrong (quadrature badly binding); 0.03 means
  it is nearly exact.
- **Held (c1) / (c1) cos** — same comparison for the residual's *gradient*
  (what the solver actually follows): relative error and cosine alignment.
- **Held recon** — decoder reconstruction error on held-out states; identical
  in both arms here because the decoder is frozen.
- **vs base** — relative change in rollout error of the learned-node arm
  against the NNLS baseline at the same $N$ and $m$.
- **Trip** — the tripwire that flags any held-out reconstruction drift > 3%;
  cannot fire with a frozen decoder, and did not.
- **Gate R / H / 0 / C / D / L** — pre-flight identity checks (data-draw
  reproduction, parameter split, sampled-operator closure, continuous-node
  machinery, gradient correctness, exact linear terms). All passed in every
  completed job.
- **Checkpoint** — the saved trained decoder for a mesh. One per N; results
  are conditional on it (this project has measured checkpoint-dependent sign
  flips before).
