Do iterations or decoding depend on the mesh?

Iterations are flat; only writing the output grows

  • Solve: r 128 ≈ 22 ms, r 256 ≈ 52 ms, r 384 ≈ 88 ms at every mesh
  • Iterations: 51.5–54.3 Levenberg–Marquardt iterations per 50 steps, same on every mesh; at most 5 in any step
  • Decode: 0.13–0.18 ms at 256² → 5.7–14.3 ms at 4096²
  • Solid BE, dashed CN-R: schemes overlap

P1 timing job 5352971 (H200), frozen test modes, 6 dev cases × 3 repeats; Codex-checked · 22

Iteration counts are Levenberg–Marquardt trial iterations per time step summed over the run (rejected trials included; a step can need 0 if the predictor is already converged). Each step also builds one Jacobian before iterating, so Jacobian builds = 50 + iterations ≈ 104 per run ≈ 2.1 per step at r = 384. Mesh flatness is shown for r = 128–384; r = 512 was timed only at 1024². the solver never sees the mesh after the initial fit, so they cannot change with it. Decode is the six output fields on the full mesh, which is the only mesh-dependent part.
