# Prospective full-point capacity amendment

This package is source-only, not a production release. `projection.json` is generated by `capacity2d.py`; its point counts are projections and must be replaced by the retained h2 rule count. Every accounting formula is in that script. It includes the expanded FE field archive, training archive, derivative candidates, retained models, bank evaluation temporaries, sparse metrics/factor guard and fit workspace. It does not claim a measured total peak or bound JAX autodiff storage.

`quadrature_blocked.py` writes every original decoder-output moment in contiguous, hashed NPY blocks. Matrix construction is identical to `output_moments`. Row scaling, target and every greedy correlation search use every point. The same NNLS limits, support caps, stopping tolerance and selected-support KKT check apply. Point blocks change summation order, so bitwise selected weights are not promised. There is no random search, omitted point, clipping or refit based on validation. Disk storage is separately bounded; each block and resident workspace stay bounded. Repeated complete dictionary passes can be I/O expensive and are offline costs, not a claimed speedup. Raw moment blocks remain recoverable evidence.

The synthetic comparison confirms identical raw moments and selected indices for multiple block sizes on a polynomial control. An initial strict coefficient-weight comparison differed beyond its relative tolerance on a small weight; this was not a physical gate. Coefficient uniqueness/stability is not guaranteed for this NNLS representation, so the final control records the actual weight discrepancy and tests the full moment objective, raw matrix identity and support identity instead. Full moment discrepancies are in the generated JSON. All physical tolerances are unchanged.

This code is not wired into `pilot2d.py`. Production still enforces the original point/archive limits. Required follow-up: review and integrate a per-array volume archive schema, measure actual native preparation/model peak RSS, freeze the exact point ceiling and persistent-disk reserve, and independently review the complete execution package. The current 16 GiB process and 1 GiB single-array caps are not silently raised.

The h2 result does not yet pass the physical divergence threshold, so the capacity projection now includes a fourfold-point h3 contingency. At that size even individual momentum-gradient arrays exceed the existing array cap. `fe_blocks.py` proposes native evaluation in original mapped-point blocks, preserving transformation lifetime and wrapped boundary gradients. The pure NumPy control covers its all-point TSQR candidate reduction: it preserves singular values without squaring the condition number, then applies the original ordered candidate decisions and singular-value cutoff on the small factor. The selected triangular factor uses an explicit positive-diagonal sign convention; this can flip legacy dense QR column signs but leaves the test space and metric unchanged. This is prospective source, not native-verified or wired into production. Point-blocked volume export/consumption and one-model-at-a-time execution are still required for h3; no memory-mapped oversized array is silently exempted from existing caps.

`point_store.py` supplies a versioned point-block volume archive and a bounded reader. The writer keeps shared geometry once, then evaluates each FE coefficient field through the native-validated mapped block path and saves values and dimensionless gradients without a full gradient-bank allocation. Every field covers the identical original ordered point ranges. Each payload, total compressed/expanded storage and free-disk reserve are checked. The reader verifies file hashes/coverage/shapes/original float64 and yields one complete point block. The retained-native-array serialization control replays every original point exactly; it mocks only the evaluator already validated by native-block02, not an admission or physical model.

The adapter exposes this as explicit `point_block_volume=True`, and the preparation entry requires the exact release to bind that choice. Default production caps and the old layout remain unchanged. The current accuracy loader explicitly rejects the new layout until its streaming operator/projection consumer is integrated and reviewed; it never concatenates an oversized full gradient bank as a fallback. The new source is not an end-to-end completion claim.
