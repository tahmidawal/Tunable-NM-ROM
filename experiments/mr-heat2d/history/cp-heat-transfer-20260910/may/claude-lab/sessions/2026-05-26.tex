\section{2026-05-26}

\sessionhead{1}{morning}{heat3d-n128-push}{eq-dof-scaling-cp}{(uncommitted)}

\subsubsection*{Summary}
Pushed the 3D Heat NM-ROM at $N=128$ from a failure (ROM rel-$L^2$ mean
$8.86\mathrm{e}{-2}$, worse than $N=64$) to the new champion
(ROM rel-$L^2$ mean $2.36\mathrm{e}{-2}$, $1.55\times$ \emph{better} than
$N=64$ hi3). The original failure was \emph{not} a modelling issue ---
it was two undertuned hyperparameters: (1) the autoencoder was cut
short before convergence and (2) the empirical-quadrature (EQ) node
count was inherited from $N=64$ and never scaled with the grid.

\subsubsection*{Decisions / surprises}
\begin{itemize}
  \item \textbf{Stacked warm-starts beat capacity bumps.} The first three retrains pushed encoder/decoder capacity (rank $2048 \to 4096 \to 6144$, embed $192 \to 256 \to 320$). All three were \emph{worse} than the original \texttt{hi}. Inspecting the training-loss histories showed the train/val gap was constant at ${\sim}3.3\times$ across all architectures: bigger models simply trained slower at the same epoch budget. \texttt{hi}'s best val landed at epoch $261$k of $300$k, still actively improving. The real limiter was undertraining, not under-capacity.
  \item \textbf{EQ density was the silent bottleneck on the ROM side.} At $N=64$ the default 2048 EQ nodes is 0.78\% of the grid; at $N=128$ the same count is 0.10\% --- an 8$\times$ sparser hyper-reduction. AE val kept improving but ROM rel-$L^2$ plateaued, signalling that the GN solver was minimizing the wrong loss. Rebuilding EQ at $\geq$8192 nodes on the existing \texttt{hi\_cont\_big} checkpoint dropped ROM rel-$L^2$ from $5.23\mathrm{e}{-2} \to 2.92\mathrm{e}{-2}$ with no retraining. This was the moment $N=128$ first beat $N=64$ hi3.
  \item \textbf{NNLS subsample seed matters.} Two \texttt{min\_eq=8192} runs with different \texttt{max\_candidates} gave $2.85\mathrm{e}{-2}$ vs $3.48\mathrm{e}{-2}$ --- not a knob effect, but a random-subsample-of-the-residual-equations effect. Added \texttt{-{}-eq-seed} so this can be averaged over going forward.
  \item \textbf{Hardware shape changed mid-run.} The first $N=128$ attempt requested $1500$\,G on H200 and never started; all 32 H200 GPUs were allocated for 1--2 days. The streaming \texttt{.dir} fix dropped the memory request to $400$\,G and let the job land on the much-more-available A100 nodes.
\end{itemize}

\paragraph{Changes that moved error down.}
\begin{enumerate}
  \item \textbf{Lifted the $N=128$ data ceiling.} The paper's
  $n_\mathrm{train}{=}100$ was set ``due to memory'' (paper draft, line
  650). Root cause: \texttt{np.savez} on the full $428$\,GB dataset
  needed ${\sim}860$\,GB peak host RAM and stalled. New streaming
  \texttt{.dir} layout (\texttt{utils/dataset\_io.py}) writes each
  batch directly into a memmapped \texttt{.npy} file; host RAM peak
  drops to a few GB per chunk. Lets us train $N=128$ on $1000$
  trajectories at $400$\,G SLURM mem instead of failing at $1500$\,G.
  \item \textbf{Stacked warm-starts replace the one-shot $40$k-epoch
  schedule.} Added \texttt{-{}-init-ckpt} to \texttt{scripts/train.py}
  so a prior checkpoint warm-starts the AE while the optax
  warmup-cosine schedule restarts fresh. Six rounds of $300$k--$400$k
  epochs each, peak LR halved each round
  ($1.2\mathrm{e}{-3} \to 6\mathrm{e}{-4} \to \ldots \to 2\mathrm{e}{-4}$).
  AE val: $1.31\mathrm{e}{-2} \to 7.24\mathrm{e}{-3} \to
  5.45\mathrm{e}{-3} \to 3.45\mathrm{e}{-3} \to 2.76\mathrm{e}{-3}$.
  \item \textbf{Bigger batch in the late-stage rounds.} Decoder peak
  intermediate at rank $2048$, $N{=}128$ is only $134$\,MB/sample, so
  batch $4 \to 16$ fits comfortably on 80\,GB A100. Cleaner gradients
  let the cosine schedule actually converge; this was the round that
  broke AE val below $4\mathrm{e}{-3}$.
  \item \textbf{Scaled EQ-node count with grid.} The paper used
  $N_\mathrm{eq}{=}1280$ for $N{=}128$ --- $0.06\%$ of the grid versus
  $0.78\%$ at $N{=}64$, so the hyper-reduction was sampling $8\times$
  less densely. Added CLI overrides
  \texttt{-{}-min-eq-points}, \texttt{-{}-n-eq-samples}, \texttt{-{}-max-candidates},
  \texttt{-{}-eq-seed} to \texttt{scripts/run\_rom.py}. Bumping to
  $8192$ EQ nodes on the same trained checkpoint dropped ROM from
  $5.23\mathrm{e}{-2}$ to $2.85\mathrm{e}{-2}$ with no retraining.
  This is what made $N=128$ first beat $N=64$.
  \item \textbf{Chunked NNLS design-matrix transfer.} The previous
  \texttt{eq/nnls.py} pushed all $2048 \times 128^3$ snapshots
  ($34$\,GB) onto the GPU before computing residuals, which OOM'd on a
  shared A100. Refactored to stage host $\to$ device per chunk;
  enabled the dense EQ sweeps above.
\end{enumerate}

\paragraph{Caveats.} (i) The paper reports $191\times$ speedup at
$N{=}128$ at the cheap $N_\mathrm{eq}{=}1280$ setting; this session's
$2.36\mathrm{e}{-2}$ runs at $\sim$$0.20\times$ at
$N_\mathrm{eq}{=}8192$. The comparison above is accuracy-only.
Refreshing the Pareto curve on \texttt{hi\_cont\_big2} (sweep GN cap
and $N_\mathrm{eq}$ jointly) is the natural next step. (ii) The new
$N=32$ and $N=64$ numbers come from existing checkpoints
(\texttt{heat3d\_n32\_hi.pkl}, \texttt{heat3d\_n64\_hi3.pkl}) trained
earlier on this branch with EQ density already raised; the EQ density
fix landed at the same time as the $N{=}128$ chain.

\subsubsection*{Loss / optimizer (for the record)}
Reconstruction loss is per-sample squared relative $L^2$,
\[
\mathcal{L}(\theta) = \frac{1}{|B|} \sum_{u \in B}
  \frac{\|f_\theta(u) - u\|_2^2}{\|u\|_2^2 + 10^{-6}},
\]
with $f_\theta = D_\theta \circ E_\theta$ the ViT encoder + CP-tensor
decoder.  Optimizer is \texttt{optax.adamw}, weight decay
$5\mathrm{e}{-3}$, warmup-cosine-decay schedule
(\texttt{init=0}, \texttt{peak\_value=peak\_lr}, \texttt{end=1e-6}),
default Adam betas/eps.  Each \texttt{-{}-init-ckpt} restart reinitializes
the LR schedule from epoch 0 (fresh warmup + cosine), with a
successively lower \texttt{peak\_lr} ceiling each round.
