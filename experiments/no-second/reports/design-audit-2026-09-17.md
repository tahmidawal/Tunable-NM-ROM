# Independent design audit of `experiments/no-second` (2026-09-17, before the first job)

Auditor: an independent Claude subagent given a read-only adversarial brief (Codex, the
protocol's preferred auditor, could not run: its bubblewrap sandbox failed to start and the
account then hit its usage limit until 2026-09-19; see `codex-design-audit.md`). Audited at
worktree HEAD `e71075a7`; staged blobs at `219abe81` verified byte-identical to the working
tree. Findings reproduced verbatim below; the actions taken on each are in `DESIGN.md` §A1.

---

1. **MAJOR — G4's 1e-11 tolerance compares two different float32 forward passes.** `train.py:167` computes the stated `validation.errors` with batch 8; `train.py:169-173` writes the per-case predictions with batch 1. `audit.py:92` then requires `rtol=1e-11` agreement between the numbers recomputed from those batch-1 fields and the batch-8 stated errors (and `audit.py:100` requires 1e-12 between the in-loop and post-restore batch-8 evaluations). For the f64 FFT-based FNO this held (parity gap 1.6e-16). For f32 cuDNN convs / cuBLAS batched GEMMs, kernel/split-K choice depends on the batch dimension; no determinism flag is set anywhere (`model.py:26-41`, no `cudnn.deterministic`). Expect ~1e-7 relative drift → G4 trips spuriously on every f32 arm, or the tolerance gets loosened after seeing data (post-hoc). Neither smoke tests batch-N vs batch-1 consistency (`training_smoke_second.py:51`, `smoke_second.py:62-82` use one batch size). Fix before submission: write the prediction files from the same batched `evaluate` pass (or derive `result.validation.errors` from the saved fields), and pre-register the float32 tolerance in DESIGN.

2. **MAJOR — The SIGUSR1 stop path is dead: `run.sbatch` no longer `exec`s the worker.** `cluster/stage.py:76` requests `--signal=B:USR1@180` (batch shell only); `stage.py:102-104` runs the worker as a child and then `find … > OUTPUTS.sha256; echo ALL-DONE`. The parent used `exec` (`../neural-operator-audit/stage_burgers.py:93`), so its worker received USR1. Here bash gets USR1 with default disposition (terminate): the worker's handler (`worker_second.py:36-44`) and `train.py:193-194` never fire, and if the worker is still running at T-180 the trailer never runs, `ALL-DONE` is missing, and `collect.py:47` refuses the job. In practice the worker's own clock saves it (see 12), so this is robustness, but the DESIGN's "signal" stop reason (G5) cannot occur. Fix: `trap 'kill -USR1 $pid' USR1; "$PY" code/worker_second.py … & pid=$!; wait $pid`, or move the trailer into the worker and `exec`.

3. **MAJOR — `audit.py` can report `passed=True` with an arm dropped or the cohort missing.** `audit.py:203` passes if every *found* `prefix-*` folder is complete; an arm skipped for budget (`worker_second.py:76`, no folder) or a failed cohort-eval (`allow_failure=True`, `worker_second.py:126`; `audit.py:120-121` returns `present=False`) both pass, so G3's cohort-hash assertion (`audit.py:122`) and G5 ("every arm is reported") are not actually enforced. Fix: assert `set(arms) == {small, medium, large, refine}` (or record skips explicitly) and require `cohort.present`.

4. **MAJOR — V1's "validation-selected arm" is ambiguous about `refine`, and the FNO reference is hard-coded.** DESIGN §4 V1 says "validation-selected arm"; `reports/generate_report.py:186-195` takes argmin of validation *mean* over all complete arms including `refine`, while the FNO side is `fno_sel = 'fno-large'` (`generate_report.py:200`) rather than the same rule applied to the FNO audit. It happens to coincide today (fno-large mean 0.02281 < fno-refine 0.02350) but the rule must be written down (also note fno-medium had the lower worst/median, 6.04 %/1.76 %, so V1's 1.5× thresholds are pinned to the mean-selected arm; say so). Fix: amend §A1 "arm = argmin validation mean over {small, medium, large, refine}; the same rule defines the FNO reference" and derive `fno_sel` in code.

5. **MINOR — `audit.py` records but never asserts the protocol.** `audit.py:101-105` copies `config`, `seed`, `parameter_dtype` without checking `epochs==4000, patience==250, batch_size==8, learning_rate∈{1e-3,3e-4}, weight_decay==1e-4, seed==20260914`, or that `config_sha256` matches a staged config (refine excepted). A wrong config would audit clean. Fix: assert these against the FNO's burgers-long config values.

6. **MINOR — "zero padding is the natural extension of a zero-Dirichlet field" is false as implemented.** `pad_to_multiple` (`families.py:62-68`) is applied at `families.py:101` and `:185` to the *normalised* features: the padded ring is 0 where the true boundary value is −mean/std, and the constant viscosity channel drops to 0 there. Cropped and masked, so not a correctness bug, but the rationale in DESIGN:55-56 / `families.py:22-24` is wrong and the ring is a fixed discontinuity both nets must learn around. Fix: pad each channel with its normalised zero, or reword.

7. **MINOR — Transolver deviates from the upstream structured-mesh code in four places, none disclosed.** (a) temperature clamp `(0.01, 5)` at `families.py:142` vs upstream `min=0.1` (verify against upstream); (b) 4×4 patch tokens (`families.py:185-188`) — the paper's structured variant uses per-node tokens on a downsampled grid, so "structured-mesh variant" (DESIGN §3.2) is not accurate and the decoder emits 16 pixels per token linearly; (c) decoder is LN + 2-layer MLP (`families.py:178`) vs upstream LN + Linear, and the module docstring `families.py:34` says "linear map" while DESIGN §3.2 says MLP; (d) `placeholder` added unconditionally (`families.py:200`; upstream only without function input) — harmless. Fix: match the clamp or justify; describe as "patchified"; fix the docstring.

8. **NOTE — U-Net is not PDEBench's norm/activation.** PDEBench `unet.py` uses BatchNorm2d + Tanh; the lane uses GroupNorm(8) + GELU (`families.py:79-82`). Topology, widths, bias-free convs, ConvTranspose up and 1×1 head match, and counts are verified analytically (4 368 389 / 7 763 461 / 17 462 021). Fix: label as "PDEBench topology with GroupNorm/GELU".

9. **NOTE — No transposition or padding bugs found.** Verified analytically: 257→272 (pad 15: top 7, bottom 8, crop `[7:264]`), 65→80, 257→260 (top 1, bottom 2), pools 272→136→68→34→17, all channel concatenations consistent (`families.py:90-110`). Transolver patch/unpatch (`families.py:188`, `:205`), head split (`:134-136`) and deslice (`:148-150`) reproduced in numpy against the upstream `b n (h d)` ordering: bit-exact round trip. Token centres (`:194-195`) extrapolate the unpadded linspace correctly. Slice weights/mass normalisation/attention match upstream (`:142-148`).

10. **NOTE — Precision handling is sound.** `Precision.forward` casts in and back (`families.py:57-59`); `predict` scale/mask/cat are f64 (`model.py:91-99`); saved predictions are f64 (`train.py:172`) and asserted so (`audit.py:57`). `model.py:32-34` disables TF32 for cuBLAS and cuDNN and sets matmul precision highest before any model is built; conv/convT/einsum/bmm all covered; SDPA not used. Residual: no cuDNN determinism → see 1.

11. **NOTE — warmup / ReduceLROnPlateau do not interact badly.** `train.py:118-120` overwrites `lr` for epochs 0-9; a reduction needs 21 stale epochs (`train.py:111`), and `_reduce_lr` reads the live `param_group['lr']` (`torch/optim/lr_scheduler.py:1735`). The Transolver refine inherits `warmup_epochs=10` (`worker_second.py:113-115`) so it warms up to 3e-4 — fine, but undocumented in DESIGN §3.2.

12. **MINOR — Stop flags are not mutually exclusive.** `stopped_by_wall_budget` is evaluated at `train.py:177` after the final evaluation and 32 prediction writes, so it can be true alongside early-stopping/epoch-cap; `stopped_by_signal=STOP` (`:176`) reflects any signal up to result-writing. `audit.stop_reason` (`audit.py:68-71`) resolves by fixed priority, which is defensible but should be stated. Also the 4000-epoch cap is plausibly reachable by `unet-small` in f32 (fno-small did 1741 epochs in 3000 s in f64), which would end an arm below budget — the falsification clause only distinguishes wall vs early stopping. Fix: capture the loop-exit reason at the `break`, and pre-register how a cap-ended arm is read.

13. **NOTE — Wall arithmetic is safe.** 4×3000 + 900 = 12 900 < 15 600 global; parent measured 3011-3015 s per arm and ~30 s preamble, so ≈12.2 ks expected; the 16 800 s limit leaves ≥1 200 s over the worker deadline for the cache copy+sha256 and trailer. Cohort-eval/timing (`worker_second.py:126-130`) run unbudgeted but took 56 s in the parent. **MINOR:** `--gres=gpu:a100:1` without the parent's `--constraint=a100-80G` (`stage.py:71`) allows a 40 GB A100, weakening "3000 s on one A100"; the GPU name is at least recorded (`audit.py:183`).
