# Fixed-checkpoint Poisson online tuning

This is a predeclared development screen and confirmation protocol. No new numerical results exist when this protocol is committed. The existing approved Poisson worktree and namespace are continued; checkpoint weights and the final evaluation cohort remain untouched.

The `config-online-tuning.json` file declares every setting before timing. All settings use the same frozen original-relative checkpoint and all existing development source fields. Only the online solver work, source-based starting effort, and offline-prepared weak mode set change. Spatial and head weights, latent dimension and bank size are fixed. Weak operators and training-code predictions are rebuilt offline for each mesh and requested mode count; eigenvalue shells can retain more modes than requested. Retained mode count is recorded. There is no empirical quadrature.

The first stage tests every preset on the coarse mesh. This includes intentional iteration truncations and loose optimality stops: these are diagnostic candidates and are never relabelled stationary. A new in-loop normalized-gradient stop uses reason 6; default `None` leaves the previous kernel schedule and stops unchanged. Numerical eligibility retains the previous post-solve stationarity tolerance or achieved relative-residual-target rule. Linear-solve backward errors are checked for every attempted start. Multiple starts use nearest cached weak predictions from training codes, and choose by the smallest terminal weak residual; physical truth is never used to choose a start.

Before any confirmation timing, the driver writes and hashes the coarse-screen selectors and the unique shortlist: baseline, fastest finite diagnostic, smallest worst full-field physical error among complete-cohort stationary settings, unrestricted physical-error winner as a separate diagnostic, fastest passing the existing physical/reference/numerical gate if any, and fastest stationary setting if any. Ties are resolved by pooled GPU median then stable setting identifier. The same shortlist is rerun at every requested mesh. Reported mesh-specific extrema are selections within that frozen shortlist on already-open development cases, not an independent final test or global optimum. All screen results remain in the archive. If no setting passes the unchanged target, that absence is reported.

Each phase includes the same five iterative CG tolerances and the direct DST diagnostic. Every phase/method/case retains all timing repetitions and the exact full output from each invocation, with content deduplication. Burn-in precedes every timed block. The GPU interval includes full-source projection, initialization and every solve, selection and full decoding; host total also includes full input/output transfers and online solver metadata. Post-timer stationarity checks are explicitly audit-only. Medians pool all equal-count repetitions to match the coordinator report. Different phases have separate results; all within-phase speed ratios are same-job and same-GPU.

The batch job verifies GPU backend, f64, highest precision, code and checkpoint hashes. Cluster data is regenerated from seed. Collection verifies every manifest, splits a restorable archive into tracked parts and deletes only the exact completed attempt. Independent CPU audit reconstructs banks/operators, source projections, latent fields, residuals, gradients, stops, every physical error and CG true residual. A bounded source-level GPU fixture checks baseline parity, real stationarity stopping, budget exits and multistart choice.

Glossary: **preset** is one fixed combination of online controls; **M** is the number of weak test modes; **k** is the latent dimension; **stationarity** is a normalized objective-gradient check; **CG** is conjugate gradients; **DST** is the direct discrete sine transform Poisson solver; **screen** chooses candidates from development data; **confirmation** reruns the frozen shortlist with new timings but the same development sources; **paired** means each cost and error belongs to the same solver invocation.
