The verifier reconstructs every file byte stream directly from the pinned Git blobs, checks every file SHA256, checks each split part and the concatenated tar checksum, and validates hard links for identical contents. It does not rely on ignored local field files as proof. Original `RETENTION.json` records retain their historical scope; each attempt's `SCIENTIFIC-RETENTION.json` links the correction. The earliest pilot has its original output manifest but no subsequent full-collection manifest; that narrower original checksum scope is explicit in its archive manifest.

To verify an archive from this worktree, replace the attempt and Git source with the corresponding table entries:

```bash
/home/tahmid/Dev/.venv/bin/python experiments/paper-b3d/scientific_archive.py verify b3d005 --commit 7528fba6
```

To materialize the scientific files, concatenate that attempt's `scientific.tar.part*` files in lexical order and extract the resulting tar into a new directory. The manifest paths are relative to the original collected directory. Verify the archive before using reconstructed fields in a report.

Regenerable training arrays and optimizer continuation states are explicitly listed in each manifest. They remain untouched in the original local collection and are not claimed to be recoverable from this scientific archive. These tables are generated by `generate_retention_report.py` from the saved restore audits.

## Glossary

- **Scientific field:** an exact saved numerical prediction or reference used to audit a reported result.
- **Paired record:** accuracy and runtime recorded from the same solver invocation.
- **Split part:** a consecutively numbered piece of one lossless tar archive.
- **Tar bytes:** size of the complete concatenated archive, including metadata.
- **Restored file bytes:** total sizes of reconstructed files, including repeated identical files restored from hard links.
- **Hard link:** an archive entry reusing an earlier identical file's bytes while preserving its own pathname.
- **SHA256:** a checksum used to detect any change in file content.
- **Git source:** the commit containing the exact archived bytes used by the restore audit.
- **Optimizer continuation state:** training bookkeeping needed to resume optimization; distinct from the selected trained prediction model.
